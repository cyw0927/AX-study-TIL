# 06. 오류 메시지 읽는 법과 디버깅

Python을 배우면 오류는 반드시 나온다. 오류가 뜨는 건 이상한 일이 아니라, 프로그램이 **어디가 잘못됐는지 알려주는 과정**이다.

## 1. 오류 메시지가 길어도 마지막 줄부터 보기

Python 오류는 여러 줄로 나오기도 한다.

예:

```text
Traceback (most recent call last):
  File "test.py", line 3, in <module>
    number = int("abc")
ValueError: invalid literal for int() with base 10: 'abc'
```

처음 보면 무섭지만 우선 마지막 줄을 본다.

```text
ValueError: ... 'abc'
```

여기서 오류 종류가 `ValueError`라는 걸 알 수 있다.

그리고 위쪽에서 어느 줄에서 났는지 본다.

```text
line 3
```

---

## 2. `SyntaxError`

문법 자체가 잘못됐을 때 나온다.

```python
if 10 > 5
    print("맞음")
```

`if` 뒤에 `:`가 빠졌다.

정상:

```python
if 10 > 5:
    print("맞음")
```

`SyntaxError`가 뜨면 먼저 괄호, 따옴표, 콜론 같은 문법 기호를 확인한다.

---

## 3. `IndentationError`

들여쓰기가 잘못됐을 때 나온다.

```python
if 10 > 5:
print("맞음")
```

정상:

```python
if 10 > 5:
    print("맞음")
```

Python에서 들여쓰기는 단순히 보기 좋게 만드는 것이 아니라 문법의 일부다.

---

## 4. `NameError`

없는 변수 이름을 사용했을 때 자주 나온다.

```python
print(age)
```

그런데 그 전에 `age`를 만든 적이 없다면 오류가 난다.

또는 오타일 수도 있다.

```python
name = "철수"
print(nmae)
```

`name`과 `nmae`가 다르다.

---

## 5. `TypeError`

자료형이 맞지 않는 연산을 했을 때 자주 나온다.

```python
age = "20"
print(age + 1)
```

문자열과 숫자를 더하려고 해서 오류가 난다.

정상:

```python
age = int("20")
print(age + 1)
```

이럴 때 `type()`을 찍어보면 원인을 찾기 쉽다.

```python
print(type(age))
```

---

## 6. `ValueError`

자료형 변환 방식 자체는 가능하지만 **값이 이상해서** 변환할 수 없을 때 자주 나온다.

```python
number = int("abc")
```

`int()`는 문자열 숫자를 정수로 바꿀 수 있지만 `"abc"`는 숫자가 아니므로 실패한다.

---

## 7. `IndexError`

리스트에 없는 위치를 꺼내려고 했을 때 나온다.

```python
numbers = [10, 20, 30]
print(numbers[3])
```

이 리스트의 인덱스는 0, 1, 2까지만 있다.

그래서 `[3]`은 없다.

확인할 때:

```python
print(len(numbers))
```

를 써 보면 좋다.

---

## 8. `KeyError`

딕셔너리에 없는 키를 꺼내려고 했을 때 나온다.

```python
person = {"name": "철수"}
print(person["age"])
```

`age`라는 키가 없기 때문이다.

---

## 9. `ZeroDivisionError`

0으로 나누려고 하면 나온다.

```python
print(10 / 0)
```

수학적으로도 0으로 나눌 수 없기 때문이다.

---

## 10. `FileNotFoundError`

파일을 열려고 했는데 그 위치에 파일이 없을 때 나온다.

```python
open("data.csv")
```

현재 폴더에 `data.csv`가 없으면 오류가 날 수 있다.

이 오류는 코드 문제라기보다 **현재 작업 폴더와 파일 위치 문제**인 경우가 많다.

---

## 11. `KeyboardInterrupt`

프로그램 실행 중 사용자가 `Ctrl + C`로 강제로 중단했을 때 보게 된다.

예를 들어:

```python
name = input()
```

실행 후 아무것도 입력하지 않으면 프로그램은 입력을 기다리고 있다.

그 상태에서 `Ctrl + C`를 누르면 `KeyboardInterrupt`가 나올 수 있다.

즉 이것은 항상 코드 오류라는 뜻은 아니다.

---

## 12. 디버깅이란?

디버깅은 **코드에서 문제가 나는 이유를 찾아 고치는 과정**이다.

처음부터 어려운 도구를 쓸 필요는 없다.

초보에게 가장 강력한 디버깅 도구는 사실 `print()`다.

예:

```python
text = "255,0,0"
parts = text.split(',')

print("parts:", parts)
print("type:", type(parts))
print("length:", len(parts))
```

이렇게 중간값을 눈으로 확인한다.

---

## 13. 마지막 결과만 보지 말기

결과가 이상하다고 마지막 줄만 계속 고치면 원인을 못 찾을 수 있다.

예를 들어:

```text
입력 문자열
↓
split 결과
↓
int 변환 결과
↓
밝기 계산
↓
평균 계산
↓
최종 결과
```

이 순서에서 **처음으로 예상과 달라진 곳**을 찾는 게 중요하다.

---

## 14. 한꺼번에 긴 코드 돌리지 말기

오류가 난다면 문제 부분만 아주 작게 떼어낸다.

예를 들어 이 코드가 이해 안 된다면:

```python
r, g, b = map(int, pixel.split(','))
```

한 번에 보지 말고:

```python
pixel = "255,0,0"
print(pixel)
```

그다음:

```python
parts = pixel.split(',')
print(parts)
```

그다음:

```python
numbers = list(map(int, parts))
print(numbers)
```

처럼 나눈다.

이 방식이 초보에게 특히 중요하다.

---

## 15. 예상값 먼저 적기

코드를 실행하기 전에 결과를 예상해 본다.

```python
x = 10
x += 5
print(x)
```

실행 전에 `15가 나오겠지`라고 예상한다.

실제 결과가 15면 이해가 맞았던 것이고, 다르면 왜 다른지 확인한다.

그냥 실행 버튼만 누르고 결과를 보는 것보다 훨씬 공부가 된다.

---

## 16. `type()`, `len()`, `print()` 세 개를 적극적으로 쓰기

코드가 이상할 때 우선 확인할 것:

```python
print(value)
print(type(value))
print(len(value))
```

물론 `len()`은 길이를 셀 수 있는 자료형에만 사용한다.

이 세 개만 잘 써도 초보 단계의 많은 오류를 직접 추적할 수 있다.

---

## 17. `try` / `except`

오류가 날 수 있는 코드를 안전하게 처리하는 문법이다.

```python
try:
    number = int("abc")
except ValueError:
    print("숫자로 바꿀 수 없습니다")
```

결과:

```text
숫자로 바꿀 수 없습니다
```

처음에는 완벽하게 외울 필요 없다.

대충:

> try에서 해보고, 특정 오류가 나면 except 쪽으로 간다.

정도로 이해하면 된다.

---

## 18. 오류 질문을 AI에게 할 때

그냥:

```text
안돼
```

라고 하면 원인을 찾기 어렵다.

가능하면 다음을 같이 준다.

```text
1. 실행한 코드
2. 오류 메시지 전체
3. 입력한 값
4. 원래 기대한 결과
5. 실제 나온 결과
```

특히 오류 메시지는 임의로 줄여서 중요한 부분을 빼지 않는 것이 좋다.

---

## 19. 초보용 오류 확인 순서

오류가 나면 다음 순서로 보면 된다.

1. 오류 메시지 마지막 줄 보기
2. 오류 이름 확인하기
3. 몇 번째 줄에서 났는지 보기
4. 그 줄의 변수 값을 `print()`로 보기
5. `type()`으로 자료형 확인하기
6. 리스트라면 `len()`으로 길이 확인하기
7. 긴 코드라면 작은 부분으로 쪼개서 실행하기

---

## 20. 가장 중요한 생각

오류 메시지는 컴퓨터가 나를 혼내는 문장이 아니다.

**"이 줄에서 이런 종류의 문제가 생겼다"는 힌트**다.

오류를 없애는 것보다 왜 오류가 났는지 이해하는 것이 더 중요하다.
