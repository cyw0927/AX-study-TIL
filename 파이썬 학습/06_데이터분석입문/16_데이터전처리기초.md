# 16. 데이터 전처리 기초

데이터 전처리는 데이터를 무조건 많이 지우고 바꾸는 작업이 아니다.

핵심은 다음과 같다.

```text
원본을 보존하고
↓
문제가 있는 부분을 확인하고
↓
처리 기준을 정하고
↓
처리 전후가 어떻게 달라졌는지 확인하고
↓
같은 과정을 다시 실행할 수 있게 만드는 것
```

## 1. 원본은 건드리지 않는다

```python
customers_clean = customers.copy()
products_clean = products.copy()
orders_clean = orders.copy()
order_items_clean = order_items.copy()
```

`raw` 데이터는 그대로 두고 `clean` 복사본에서 작업한다.

```text
raw
→ 원본

clean
→ 전처리용 복사본
```

원본을 바로 수정하면 무엇이 바뀌었는지 비교하기 어렵고, 실수했을 때 되돌리기도 어렵다.

## 2. 처리 전에 현재 상태부터 기록

```python
print(df.shape)
print(df.isna().sum())
print(df.duplicated().sum())
print(df.dtypes)
```

먼저 현재 상태를 알아야 전처리 후 무엇이 달라졌는지 비교할 수 있다.

결측치와 중복이 0이어도 의미 있는 결과다.

## 3. 문자열 공백 정리

문자열 데이터는 눈으로는 같아 보여도 공백 때문에 다른 값으로 인식될 수 있다.

```python
df["city"] = df["city"].str.strip()
```

예:

```text
"서울"
"서울 "
" 서울"
```

사람 눈에는 같아 보여도 컴퓨터는 다르게 볼 수 있다.

## 4. 빈 문자열을 결측치로 바꾸기

```python
df["city"] = df["city"].replace("", pd.NA)
```

공백만 있는 문자열은 먼저 `.str.strip()`으로 정리한 뒤 확인한다.

## 5. 숫자 타입 변환

숫자처럼 보이지만 문자열로 읽힌 경우가 있다.

```python
products_clean["price"] = pd.to_numeric(
    products_clean["price"],
    errors="coerce"
)
```

`errors="coerce"`는 숫자로 바꿀 수 없는 값을 `NaN`으로 만든다.

따라서 실행 후 반드시 확인해야 한다.

```python
print(products_clean["price"].isna().sum())
```

코드가 오류 없이 실행됐다고 해서 모든 값이 정상 변환됐다는 뜻은 아니다.

## 6. 날짜 타입 변환

```python
orders_clean["order_date"] = pd.to_datetime(
    orders_clean["order_date"],
    errors="coerce"
)
```

변환 후:

```python
print(orders_clean["order_date"].isna().sum())
```

으로 실패 건수를 확인한다.

## 7. str, int, float 다시 보기

```text
"30"   → str
30     → int
30.0   → float
```

같아 보이지만 타입이 다르다.

```python
"30" + "10"
```

결과:

```text
3010
```

하지만:

```python
30 + 10
```

결과:

```text
40
```

데이터 분석에서는 dtype을 확인하는 습관이 중요하다.

```python
print(df.dtypes)
```

## 8. 결측치는 무조건 지우지 않는다

예를 들어 나이가 비어 있다고 해서 해당 고객 행을 무조건 삭제하면 데이터가 줄어든다.

가능한 선택:

```text
삭제
평균값 대체
중앙값 대체
별도 범주 처리
그대로 유지
```

무엇을 선택할지는 데이터 의미에 따라 달라진다.

예:

```python
age_median = customers_clean["age"].median()
customers_clean["age"] = customers_clean["age"].fillna(age_median)
```

도시는:

```python
customers_clean["city"] = (
    customers_clean["city"].fillna("Unknown")
)
```

처럼 처리할 수도 있다.

하지만 이것도 항상 정답은 아니다.

## 9. 중복에도 종류가 있다

전체 행 중복:

```python
df.duplicated().sum()
```

고유 ID 중복:

```python
df["customer_id"].duplicated().sum()
```

둘은 다른 문제다.

그리고 FK는 원래 반복될 수 있다.

예:

```text
order_items.order_id
```

한 주문에 여러 상품이 있을 수 있으므로 같은 `order_id`가 여러 번 나오는 것이 정상이다.

## 10. 범주형 값 표준화

예를 들어 주문 상태가 다음처럼 섞여 있다면:

```text
completed
complete
완료
```

업무적으로 같은 의미라고 확인된 경우에만 하나로 맞춘다.

```python
status_map = {
    "complete": "completed",
    "완료": "completed",
    "cancel": "cancelled",
    "취소": "cancelled"
}

orders_clean["order_status"] = (
    orders_clean["order_status"].replace(status_map)
)
```

표준화하기 전에 실제 값 분포를 확인한다.

```python
orders_clean["order_status"].value_counts(dropna=False)
```

## 11. 이상값 후보와 오류는 다르다

예:

```python
customers_clean.loc[
    (customers_clean["age"] < 0)
    | (customers_clean["age"] > 120)
]
```

또는:

```python
products_clean.loc[
    products_clean["price"] <= 0
]
```

이 값들은 이상해 보이지만 바로 삭제하면 안 된다.

예를 들어:

```text
0원 상품 → 사은품일 수도 있음
0원 단가 → 프로모션일 수도 있음
음수 수량 → 반품일 수도 있음
```

따라서:

```text
이상값 후보 = 확인이 필요한 값
```

이지 무조건 오류라는 뜻이 아니다.

## 12. 파생 컬럼 만들기

날짜가 datetime 타입이라면:

```python
orders_clean["order_month"] = (
    orders_clean["order_date"]
    .dt.to_period("M")
    .astype(str)
)
```

요일:

```python
orders_clean["order_dayofweek"] = (
    orders_clean["order_date"].dt.day_name()
)
```

주문 상세 금액:

```python
order_items_clean["line_total"] = (
    order_items_clean["quantity"]
    * order_items_clean["unit_price"]
)
```

## 13. 전처리 후 관계를 다시 검사

전처리 과정에서 값이 바뀌거나 행이 제거되면 PK/FK 관계가 깨질 수도 있다.

확인할 관계 예:

```text
orders.customer_id → customers.customer_id
order_items.order_id → orders.order_id
order_items.product_id → products.product_id
```

전처리 전 정상이었다고 해서 전처리 후에도 자동으로 정상이라고 생각하면 안 된다.

## 14. 저장 후에도 다시 확인

```python
df.to_csv(
    "data/processed/customers_clean.csv",
    index=False,
    encoding="utf-8-sig"
)
```

파일이 만들어졌는지 확인한다.

```python
from pathlib import Path

path = Path("data/processed/customers_clean.csv")
print(path.exists())
print(path.stat().st_size)
```

저장한 CSV를 다시 읽어 보는 것도 중요하다.

```python
check = pd.read_csv(
    "data/processed/customers_clean.csv"
)

print(check.shape)
print(check.columns.tolist())
```

CSV로 저장했다 다시 읽으면 날짜가 문자열로 돌아갈 수도 있다.

## 15. 재현 가능한 전처리

Notebook에서 한 번 성공했다고 끝이 아니다.

전처리 코드를 스크립트로 만들어 다시 실행했을 때 같은 결과가 나와야 한다.

```powershell
python scripts/preprocess_data.py
```

좋은 전처리는:

```text
누가
언제
다시 실행해도
같은 기준으로
비슷한 결과를 만들 수 있어야 한다
```

## 정리

```text
원본 보존
↓
현재 상태 기록
↓
문자열 정리
↓
숫자/날짜 변환
↓
변환 실패 확인
↓
결측치 처리 판단
↓
중복 구분
↓
범주 표준화
↓
이상값 후보 검토
↓
파생 컬럼 생성
↓
PK/FK 재검증
↓
저장
↓
다시 읽어서 검증
↓
재실행 가능하게 만들기
```

전처리에서 중요한 것은 **많이 바꾸는 것보다 왜 바꿨는지 설명할 수 있는 것**이다.
