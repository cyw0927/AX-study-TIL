# 27. 로그인 흐름 기초

로그인은 처음 보면 기능이 많아 보여서 복잡하다. 하지만 큰 흐름은 생각보다 단순하다.

## 로그인에서 하는 일

사용자가 보통 입력하는 것은 두 가지다.

```text
아이디 또는 이메일
비밀번호
```

서버는 이 값을 받아서 저장된 사용자 정보와 비교한다.

## 아주 단순한 흐름

```text
1. 사용자가 로그인 페이지를 연다.
2. 아이디와 비밀번호를 입력한다.
3. 브라우저가 서버로 값을 보낸다.
4. 서버가 사용자 정보를 확인한다.
5. 맞으면 로그인 성공 처리한다.
6. 틀리면 오류 메시지를 보여 준다.
```

## GET과 POST

로그인 페이지를 보여 달라고 할 때는 보통 GET을 쓴다.

```text
GET /login
```

입력한 로그인 정보를 서버로 보낼 때는 보통 POST를 쓴다.

```text
POST /login
```

## Flask에서는 대략 이런 모양

```python
from flask import Flask, request, render_template

app = Flask(__name__)

@app.route("/login", methods=["GET", "POST"])
def login():
    if request.method == "POST":
        username = request.form["username"]
        password = request.form["password"]
        return "로그인 정보 받음"

    return render_template("login.html")
```

지금은 코드를 외울 필요 없다. 중요한 것은 GET일 때와 POST일 때 하는 일이 다르다는 점이다.

## HTML 폼

```html
<form method="post">
    <input name="username">
    <input name="password" type="password">
    <button type="submit">로그인</button>
</form>
```

`name="username"`으로 보낸 값은 Flask에서:

```python
request.form["username"]
```

처럼 받을 수 있다.

## 비밀번호는 그대로 저장하면 안 된다

실제 서비스에서는 비밀번호 원문을 그대로 데이터베이스에 저장하면 안 된다.

보통 비밀번호를 해시(hash)라는 형태로 바꿔 저장한다.

초보 단계에서는:

```text
비밀번호 입력
→ 안전한 형태로 바꿔 비교
→ 맞는지 확인
```

정도로 이해하면 된다.

## 로그인 성공 후에는?

서버가 사용자가 로그인했다는 사실을 기억해야 한다.

이때 자주 나오는 말이:

```text
session
cookie
token
```

이다.

처음에는 세부 구현보다 **로그인 성공 상태를 다음 요청에서도 알아야 한다**는 개념만 잡는다.

## 로그아웃

로그아웃은 서버나 브라우저가 가지고 있던 로그인 상태를 없애는 것이다.

## 전체 흐름 한 번 더

```text
로그인 화면 요청
↓
폼 입력
↓
POST 전송
↓
서버가 사용자 확인
↓
성공이면 로그인 상태 저장
↓
다른 페이지에서도 로그인한 사용자로 인식
```

로그인은 HTML 하나만의 기능도 아니고 Python 하나만의 기능도 아니다. 브라우저, 서버, 데이터베이스가 같이 움직이는 기능이다.
