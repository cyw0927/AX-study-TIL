# 32. 테스트케이스 만들기

알고리즘 문제를 풀 때 코드 한 번 실행해서 답이 맞았다고 끝내면 위험하다. 다른 입력에서도 제대로 움직이는지 확인해야 한다.

## 테스트케이스란?

프로그램에 넣어 보는 입력 예시다.

예를 들어 숫자가 짝수인지 확인하는 프로그램이 있다.

```python
number = int(input())

if number % 2 == 0:
    print("짝수")
else:
    print("홀수")
```

## 기본 테스트

```text
입력: 4
예상: 짝수
```

이것만 확인하면 부족하다.

## 다른 종류도 넣어 본다

```text
입력: 5
예상: 홀수

입력: 0
예상: 짝수

입력: -2
예상: 짝수
```

## 경계값

조건 바로 근처 값을 확인하는 것이 중요하다.

```python
if score >= 60:
```

이라면:

```text
59
60
61
```

을 확인해 보는 것이 좋다.

특히 `>`와 `>=` 실수를 찾기 쉽다.

## 리스트 문제라면

합계를 구하는 코드가 있다고 하자.

```python
numbers = [1, 2, 3]
```

다음도 생각해 본다.

```text
숫자 1개만 있는 경우
전부 0인 경우
음수가 있는 경우
같은 숫자만 있는 경우
```

## 2차원 리스트라면

```text
1행 1열
1행 여러 열
여러 행 1열
모든 값이 같은 경우
가장 작은 값만 있는 경우
가장 큰 값만 있는 경우
```

## 예상 결과를 먼저 적는다

좋은 습관:

```text
입력:
3
10
20
30

예상 결과:
60
```

그다음 실행 결과와 비교한다.

## 테스트 표 만들기

| 번호 | 입력 특징 | 예상 결과 | 실제 결과 | 확인 |
|---|---|---|---|---|
| 1 | 일반적인 값 | 60 | 직접 실행 | PASS/FAIL |
| 2 | 최소 크기 | 예상값 | 직접 실행 | PASS/FAIL |
| 3 | 경계값 | 예상값 | 직접 실행 | PASS/FAIL |

실제 결과는 직접 실행한 뒤 적는다.

## 좋은 테스트케이스의 종류

```text
1. 문제에 나온 예제
2. 가장 작은 입력
3. 가장 큰 입력에 가까운 경우
4. 조건의 경계값
5. 전부 같은 값
6. 0이 포함된 경우
7. 순서가 반대인 경우
8. 내가 코드에서 실수하기 쉬운 경우
```

## 핵심

테스트는 답을 맞히기 위한 부가 작업이 아니라 **내 코드가 어떤 상황에서 깨지는지 찾는 작업**이다.

코드가 길어질수록 테스트케이스를 먼저 몇 개 적는 습관이 도움이 된다.
