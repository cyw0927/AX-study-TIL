# 33. 알고리즘 디버깅 연습

디버깅은 틀린 코드를 고치는 과정이다. 처음에는 코드 전체를 계속 바꾸기보다 **중간값을 확인하면서 어디서부터 틀렸는지 찾는 것**이 중요하다.

## 예제

숫자 세 개의 합을 구한다고 하자.

```python
numbers = [10, 20, 30]
total = 0

for number in numbers:
    total = number

print(total)
```

결과는 60이 아니라 30이다.

## 왜 틀렸을까?

반복문 안에서:

```python
total = number
```

라고 했기 때문에 기존 값을 계속 덮어쓴다.

원래 의도는 누적이므로:

```python
total += number
```

가 되어야 한다.

## `print()`로 중간값 보기

```python
numbers = [10, 20, 30]
total = 0

for number in numbers:
    total = number
    print("number:", number)
    print("total:", total)
```

결과를 보면 `total`이 10 → 20 → 30으로 바뀌는 것을 확인할 수 있다.

## 조건문이 이상할 때

```python
score = 60

if score > 60:
    print("합격")
else:
    print("불합격")
```

문제 조건이 60점 이상 합격이라면 `>`가 아니라 `>=`여야 한다.

이럴 때 59, 60, 61을 테스트하면 쉽게 찾을 수 있다.

## 리스트 길이가 이상할 때

```python
numbers = []

for i in range(3):
    number = int(input())

print(numbers)
```

아무것도 추가하지 않았으므로 리스트는 비어 있다.

```python
numbers.append(number)
```

가 빠졌는지 확인한다.

## 2차원 리스트에서 디버깅

```python
for row in board:
    print("현재 행:", row)

    for number in row:
        print("현재 값:", number)
```

바깥 반복문과 안쪽 반복문이 각각 무엇을 보고 있는지 출력해 보면 이해가 쉽다.

## 함수가 이상할 때

```python
def add(a, b):
    result = a + b

x = add(3, 5)
print(x)
```

결과는 `None`이다.

함수 안에서 계산만 하고 `return`을 하지 않았기 때문이다.

```python
def add(a, b):
    result = a + b
    return result
```

## 디버깅 순서

```text
1. 문제에서 원하는 결과를 다시 확인한다.
2. 입력값이 제대로 들어왔는지 출력한다.
3. 자료형을 type()으로 확인한다.
4. 반복문 안에서 변수 값이 어떻게 변하는지 출력한다.
5. 조건문 경계값을 확인한다.
6. 함수라면 return이 있는지 확인한다.
7. 마지막 출력 직전 값을 확인한다.
```

## 한 번에 여러 군데 고치지 말기

여러 줄을 동시에 바꾸면 무엇 때문에 해결됐는지 알기 어렵다.

가능하면 한 가지 가설을 세우고 한 부분만 바꾼 뒤 다시 실행한다.

## 좋은 질문 방식

AI나 다른 사람에게 물어볼 때도:

```text
이 코드 왜 안 돼?
```

보다:

```text
입력은 3 5이고, 여기서 width가 5가 되어야 하는데 3이 됩니다.
이 줄 전까지의 변수값은 이렇습니다.
어느 부분부터 확인하면 될까요?
```

처럼 실제 값과 기대값을 같이 적는 편이 훨씬 좋다.

디버깅은 코드를 잘못 짠 사람만 하는 일이 아니다. 프로그램을 만들면 누구나 계속 하는 작업이다.
