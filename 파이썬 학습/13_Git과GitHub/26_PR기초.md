# Pull Request(PR) 기초

PR은 **내가 만든 변경사항을 이 브랜치에서 저 브랜치로 합쳐 달라고 요청하는 것**이다.

팀 프로젝트에서 자주 쓰인다.

예를 들어 내가 `feature/login` 브랜치에서 로그인 기능을 만들었다고 하자.

그다음 GitHub에서:

```text
feature/login → main
```

방향으로 PR을 만든다.

## 왜 바로 main에 push하지 않나?

여러 명이 같이 작업하면 누가 어떤 코드를 바꿨는지 확인하기 어렵다.

PR을 쓰면:

- 어떤 파일이 바뀌었는지 확인할 수 있다.
- 팀원이 코드를 검토할 수 있다.
- 댓글을 달 수 있다.
- 문제가 없으면 merge할 수 있다.

## 기본 흐름

```text
브랜치 만들기
↓
코드 수정
↓
git add
git commit
git push
↓
GitHub에서 PR 만들기
↓
검토
↓
merge
```

예:

```powershell
git switch -c feature/login
```

수정 후:

```powershell
git add .
git commit -m "Add login page"
git push -u origin feature/login
```

그다음 GitHub에서 PR을 만든다.

## base와 compare

PR 화면에서 자주 보는 말이다.

```text
base    = 변경사항을 합칠 대상
compare = 내가 작업한 브랜치
```

예:

```text
base: main
compare: feature/login
```

## merge

PR 검토가 끝난 뒤 변경사항을 합치는 것이다.

초보 단계에서는 PR을 **코드 합치기 요청서**라고 생각하면 충분하다.
