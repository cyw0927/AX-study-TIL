# 24. Git 충돌 해결 기초

Git에서 충돌(conflict)은 **서로 다른 작업이 같은 부분을 다르게 바꿔서 Git이 자동으로 결정하지 못하는 상황**이다.

충돌이 났다고 저장소가 망가진 것은 아니다. 어느 내용을 남길지 사람이 정해 주면 된다.

## 언제 자주 생기나?

예를 들어 두 사람이 같은 줄을 수정했다.

원래:

```python
print("hello")
```

A는:

```python
print("안녕하세요")
```

B는:

```python
print("hello world")
```

처럼 바꿨다면 Git은 어느 쪽이 맞는지 알 수 없다.

## 충돌 표시

파일 안에 이런 표시가 생길 수 있다.

```text
<<<<<<< HEAD
print("안녕하세요")
=======
print("hello world")
>>>>>>> feature/test
```

처음 보면 무섭지만 뜻은 단순하다.

```text
<<<<<<< HEAD
현재 내가 보고 있던 쪽
=======
두 버전의 경계
>>>>>>> ...
합치려는 다른 쪽
```

## 해결 방법

원하는 코드만 남기고 충돌 표시를 지운다.

예를 들어:

```python
print("안녕하세요 world")
```

처럼 직접 새 결과를 만들어도 된다.

## 해결 후

```bash
git add .
git commit -m "Resolve merge conflict"
```

merge 과정에서 충돌이 났다면 해결 후 commit하면 된다.

## VS Code에서

VS Code는 충돌 파일에서 보통 선택 버튼을 보여 준다.

```text
Accept Current Change
Accept Incoming Change
Accept Both Changes
```

대충 뜻은:

```text
Current  → 현재 내 쪽
Incoming → 들어오는 다른 쪽
Both     → 둘 다 남기기
```

하지만 버튼을 무조건 누르기보다 실제 코드 결과를 보고 결정해야 한다.

## 충돌이 났을 때 순서

```text
1. 당황해서 파일 전체를 지우지 않는다.
2. git status를 본다.
3. 충돌 난 파일을 연다.
4. <<<<<<<, =======, >>>>>>> 부분을 찾는다.
5. 어느 코드를 남길지 정한다.
6. 충돌 표시를 모두 지운다.
7. 코드를 실행해 본다.
8. git add
9. git commit
```

## `git status`가 중요하다

```bash
git status
```

충돌 중인 파일과 현재 Git 상태를 알려 준다.

문제가 생겼을 때 무작정 여러 명령어를 치기보다 먼저 `git status`를 확인하는 습관이 좋다.

## 초보 단계에서 기억할 것

충돌은 오류라기보다 **Git이 사람에게 선택을 맡긴 상태**다.

자동으로 합칠 수 없으니 사람이 최종 코드를 정하면 된다.
