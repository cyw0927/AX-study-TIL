# 1. 데이터 분석은 코드를 실행하는 일에서 시작하지 않는다

오늘 강의에서 가장 먼저 기억해야 할 내용이다.

처음 데이터 분석을 배우면 보통 다음부터 생각하기 쉽다.

```text
Python 실행
pandas 불러오기
CSV 읽기
그래프 그리기
```

하지만 실제 분석은 여기서 시작하지 않는다.

먼저 생각해야 하는 것은 다음과 같다.

```text
무엇이 궁금한가?
왜 이 내용을 확인하려는가?
무엇을 기준으로 판단할 것인가?
어떤 데이터가 필요한가?
```

즉 데이터 분석의 출발점은 **코드가 아니라 질문**이다.

질문이 명확하지 않으면 아무리 많은 코드를 작성해도 분석 결과가 어디에 사용되어야 하는지 알기 어렵다.

---

# 2. 분석 질문을 먼저 정해야 한다

예를 들어 쇼핑몰 데이터가 있다고 하자.

단순히 다음처럼 시작할 수도 있다.

```python
import pandas as pd

df = pd.read_csv("orders.csv")
df.head()
```

하지만 이렇게 데이터를 바로 읽기 전에 먼저 어떤 질문을 해결할 것인지 정하는 것이 좋다.

예:

```text
어떤 상품이 가장 많이 팔렸는가?
어떤 카테고리의 매출이 높은가?
주문 취소가 많이 발생하는 구간은 어디인가?
고객별 구매 금액 차이는 얼마나 나는가?
최근 매출이 증가하고 있는가?
```

질문에 따라 필요한 데이터와 분석 방법이 달라진다.

따라서 흐름은 다음처럼 생각할 수 있다.

```text
질문 정의
    ↓
필요한 데이터 확인
    ↓
분석 방법 결정
    ↓
코드 작성
```

---

# 3. 측정 기준을 정해야 한다

질문만 정한다고 분석이 끝나는 것은 아니다.

예를 들어 다음 질문이 있다고 하자.

```text
가장 잘 팔리는 상품은 무엇인가?
```

여기서 "잘 팔린다"는 기준이 애매하다.

다음과 같이 여러 기준이 있을 수 있다.

```text
판매 수량이 많은 상품
매출 금액이 높은 상품
주문 횟수가 많은 상품
구매 고객 수가 많은 상품
이익이 높은 상품
```

즉 분석에서는 **무엇을 측정할 것인지 기준을 먼저 정의해야 한다.**

기준이 달라지면 같은 데이터에서도 결과가 달라질 수 있다.

---

# 4. 데이터를 먼저 이해해야 한다

분석을 시작하기 전에 데이터가 어떤 형태인지 확인해야 한다.

예를 들어 CSV 파일을 불러왔을 때 다음 내용을 먼저 확인할 수 있다.

```python
df.head()
df.info()
df.shape
df.columns
```

각 명령을 통해 확인하는 내용은 대략 다음과 같다.

```text
df.head()
→ 데이터가 실제로 어떤 모습인지 확인

df.info()
→ 컬럼, 데이터 타입, 결측치 등을 확인

df.shape
→ 행과 열의 개수 확인

df.columns
→ 어떤 컬럼이 존재하는지 확인
```

데이터를 이해하지 않고 바로 분석을 시작하면 잘못된 컬럼을 사용하거나 데이터 타입 문제를 놓칠 수 있다.

---

# 5. 데이터 구조를 파악해야 한다

데이터 분석에서는 한 파일만 사용하는 경우도 있지만 여러 파일을 함께 사용하는 경우가 많다.

예를 들어 쇼핑몰 데이터라면 다음처럼 나뉠 수 있다.

```text
orders.csv
→ 주문 정보

order_items.csv
→ 주문 안에 들어 있는 상품 정보

products.csv
→ 상품 정보

customers.csv
→ 고객 정보
```

이 경우 파일마다 역할이 다르기 때문에 어떤 컬럼을 기준으로 연결할 수 있는지 확인해야 한다.

예:

```text
orders
   ↓ order_id
order_items
   ↓ product_id
products
```

따라서 분석 전에 각 테이블이나 파일이 **무엇을 의미하는지 먼저 파악하는 과정**이 필요하다.

---

# 6. 전처리는 분석 전에 데이터를 정리하는 과정이다

실제 데이터는 바로 분석하기 좋은 형태가 아닌 경우가 많다.

대표적인 문제는 다음과 같다.

```text
결측치
중복 데이터
잘못된 데이터 타입
이상한 문자열
날짜 형식 불일치
숫자에 쉼표가 포함된 경우
카테고리 이름 불일치
```

예를 들어 금액 데이터가 다음처럼 들어 있을 수 있다.

```text
12000
15,000
10000원
None
```

이 상태에서는 바로 합계를 계산하기 어렵다.

따라서 분석 전에 데이터를 일정한 형태로 정리해야 한다.

이 과정을 **전처리(Data Preprocessing)**라고 한다.

---

# 7. 전처리는 데이터를 마음대로 바꾸는 것이 아니다

전처리를 할 때 중요한 점은 데이터를 무조건 지우거나 수정하는 것이 아니다.

예를 들어 결측치가 있다고 해서 모두 삭제하면 안 된다.

먼저 다음을 생각해야 한다.

```text
왜 값이 비어 있는가?
분석에 반드시 필요한 컬럼인가?
삭제해도 전체 결과에 문제가 없는가?
다른 값으로 대체할 수 있는가?
```

중복 데이터도 마찬가지다.

완전히 동일한 행이 두 개 있다고 해서 반드시 오류라고 볼 수는 없다.

실제로 동일한 주문이 두 번 발생한 것일 수도 있기 때문이다.

따라서 전처리는 **데이터의 의미를 확인하면서 진행해야 한다.**

---

# 8. 분석 결과는 반드시 검증해야 한다

코드가 오류 없이 실행되었다고 해서 분석이 정확한 것은 아니다.

예를 들어 매출 합계를 계산했다고 하자.

```python
total_sales = df["sales"].sum()
```

Python이 오류 없이 숫자를 출력하더라도 다음을 확인해야 한다.

```text
취소 주문이 포함되어 있는가?
환불 주문이 포함되어 있는가?
금액 단위가 맞는가?
중복 주문이 있는가?
세금이 포함된 금액인가?
```

즉 분석에서 중요한 것은 다음과 같다.

```text
코드 실행 성공
≠
분석 결과가 정확함
```

결과가 현실적으로 말이 되는지 확인하는 과정이 필요하다.

---

# 9. 숫자를 만든 뒤 의미를 해석해야 한다

데이터 분석의 최종 목표는 숫자를 출력하는 것이 아니다.

예를 들어 다음 결과가 나왔다고 하자.

```text
A 카테고리 매출: 4,000만 원
B 카테고리 매출: 2,000만 원
C 카테고리 매출: 1,000만 원
```

여기에서 끝나면 단순한 집계다.

분석에서는 한 단계 더 나아가야 한다.

```text
왜 A 카테고리 매출이 높은가?
특정 상품이 매출을 대부분 차지하는가?
구매 고객 수가 많은가?
객단가가 높은가?
특정 기간의 이벤트 영향이 있었는가?
```

즉 데이터 분석은 다음처럼 연결된다.

```text
숫자 계산
    ↓
패턴 발견
    ↓
원인 추정
    ↓
추가 확인
    ↓
의미 있는 결론
```

# 10. 분석은 한 번에 끝나는 과정이 아니다

분석을 시작할 때 세운 질문이 중간에 바뀔 수도 있다.

예를 들어 처음에는 다음 질문으로 시작했다고 하자.

```text
어떤 카테고리가 가장 많이 팔리는가?
```

분석하다 보니 특정 카테고리 하나가 매출 대부분을 차지한다는 것을 발견했다.

그러면 새로운 질문이 생길 수 있다.

```text
그 카테고리 안에서 어떤 상품이 매출을 만들고 있는가?
```

다시 분석하면 또 다른 질문이 생긴다.

```text
그 상품은 어떤 고객층이 많이 구매하는가?
```

즉 분석은 다음 과정을 반복할 수 있다.

```text
질문
↓
분석
↓
결과
↓
새로운 질문
↓
추가 분석
```

# 11. AI와 함께 데이터 분석하기

LLM은 데이터 분석 과정에서 여러 역할을 할 수 있다.

예를 들어 다음과 같이 사용할 수 있다.

```text
분석 질문 만들기
데이터 컬럼의 의미 정리하기
pandas 코드 설명받기
오류 원인 찾기
전처리 방법 비교하기
분석 결과 해석 보조받기
보고서 문장 정리하기
```

하지만 AI가 제시한 결과를 그대로 정답으로 받아들이면 안 된다.

AI가 데이터의 실제 의미를 완벽하게 알고 있는 것은 아니기 때문이다.

따라서 다음 흐름이 중요하다.

```text
사람이 질문 설정
    ↓
AI 도움 활용
    ↓
코드 실행
    ↓
결과 확인
    ↓
사람이 검증
```

---

# 12. AI에게 질문할 때도 맥락이 필요하다

단순히 다음처럼 물으면 정확한 답을 받기 어렵다.

```text
이 데이터 분석해 줘.
```

조금 더 구체적으로 질문하는 것이 좋다.

예:

```text
이 데이터는 쇼핑몰 주문 데이터다.
order_id는 주문 번호이고,
customer_id는 고객 번호이며,
amount는 주문 금액이다.

월별 매출 추이를 확인하고 싶다.
먼저 필요한 전처리와 분석 순서를 설명해 줘.
```

이처럼 **데이터의 의미, 목표, 원하는 결과**를 함께 알려 주면 AI도 더 정확하게 도움을 줄 수 있다.

# 13. AI가 작성한 코드도 이해해야 한다

AI가 다음과 같은 코드를 만들어 줬다고 해도 그대로 복사만 하면 학습이 어렵다.

```python
monthly_sales = (
    df.groupby("month")["amount"]
      .sum()
      .reset_index()
)
```

이 코드를 사용할 때는 최소한 다음을 이해해야 한다.

```text
groupby("month")
→ 월별로 데이터를 묶는다.

["amount"]
→ 금액 컬럼을 사용한다.

sum()
→ 각 월의 금액을 더한다.

reset_index()
→ 결과를 다시 일반 DataFrame 형태로 만든다.
```

즉 AI를 사용하더라도 코드가 왜 동작하는지 확인하는 과정이 필요하다.

# 14. 데이터 분석의 전체 흐름

오늘 강의 내용을 가장 간단하게 정리하면 다음과 같다.

```text
1. 문제 정의
        ↓
2. 분석 질문 설정
        ↓
3. 측정 기준 결정
        ↓
4. 데이터 이해
        ↓
5. 데이터 전처리
        ↓
6. 분석
        ↓
7. 결과 검증
        ↓
8. 결과 해석
        ↓
9. 결론 및 다음 질문
```

이 흐름이 오늘 배운 내용의 핵심이다.

# 16. data 폴더

`data/`는 분석에 사용할 데이터를 보관하는 공간이다.

보통 다음처럼 나눌 수 있다.

```text
data/
├─ raw/
└─ processed/
```

의미는 다음과 같다.

```text
raw
→ 처음 받은 원본 데이터

processed
→ 전처리가 끝난 데이터
```

원본 데이터와 수정된 데이터를 구분해 두면 어떤 과정을 거쳐 데이터가 바뀌었는지 관리하기 쉽다.

---

# 17. notebooks 폴더

`notebooks/`에는 Jupyter Notebook 파일을 저장할 수 있다.

주로 다음 작업에 사용한다.

```text
데이터 확인
EDA
간단한 전처리 실험
그래프 확인
분석 아이디어 테스트
```

처음 분석할 때는 Notebook이 결과를 바로 확인하기 편하기 때문에 많이 사용된다.

---

# 18. src 폴더

`src/`에는 실제 Python 코드 중 재사용할 기능을 모아둘 수 있다.

예:

```text
데이터 불러오기
데이터 전처리
분석 함수
시각화 함수
공통 유틸리티
```

Notebook 안에 모든 코드를 길게 작성하기보다 반복되는 기능을 함수로 빼서 관리할 때 사용한다.

---

# 19. scripts 폴더

`scripts/`에는 직접 실행하는 Python 스크립트를 둘 수 있다.

예:

```text
데이터 전처리 실행
분석 자동 실행
보고서용 데이터 생성
```

Notebook은 실험과 확인에 편하고, script는 반복 실행할 작업을 자동화하는 데 유리하다.

---

# 20. reports 폴더

`reports/`에는 분석 결과물을 저장한다.

예:

```text
분석 결과 문서
그래프 이미지
요약 보고서
발표 자료용 결과
```

분석 과정과 최종 결과를 분리해서 관리할 수 있다.

# 21. prompts 폴더

이번 프로젝트에서는 LLM을 활용하기 때문에 `prompts/` 폴더도 만들었다.

여기에는 반복해서 사용할 프롬프트를 저장할 수 있다.

예:

```text
데이터 품질 점검 프롬프트
EDA 요청 프롬프트
분석 결과 검증 프롬프트
보고서 요약 프롬프트
```

AI에게 매번 즉흥적으로 질문하는 것보다 잘 동작하는 프롬프트를 저장해 두면 재사용하기 편하다.

# 22. automation 폴더

`automation/`은 반복 작업을 자동화하기 위한 코드를 모아둘 수 있다.

```text

보고서 자동화
```

처음부터 모든 자동화를 만들 필요는 없지만 프로젝트가 커질수록 이런 구조가 도움이 될 수 있다.

# 23. .env.example

`.env` 파일에는 API Key 같은 민감한 정보가 들어갈 수 있다.

예:

```text
OPENAI_API_KEY=...
```

이 파일을 그대로 GitHub에 올리면 안 된다.

대신 `.env.example`에는 필요한 환경변수 이름만 예시로 적어 둘 수 있다.

예:

```text
OPENAI_API_KEY=
```

그리고 실제 `.env`는 `.gitignore`를 통해 Git 추적에서 제외한다.

# 24. requirements.txt

`requirements.txt`에는 프로젝트에 필요한 Python 라이브러리를 기록한다.

예:

```text
pandas
numpy
matplotlib
jupyter
```

다른 컴퓨터에서도 다음 명령으로 같은 라이브러리를 설치할 수 있다.

```bash
pip install -r requirements.txt
```

프로젝트 환경을 다시 만들 때 중요한 파일이다.

# 25. 오늘 배운 핵심 정리

오늘 내용을 다시 짧게 정리하면 다음과 같다.

### 1. 분석은 질문부터 시작한다.

```text
코드 작성
보다 먼저
무엇을 알고 싶은지 정의
```

### 2. 데이터의 의미를 먼저 이해한다.

```text
컬럼
데이터 타입
결측치
파일 간 관계
```

### 3. 전처리는 분석을 위한 데이터 정리 과정이다.

```text
결측치
중복
타입
형식
```

### 4. 코드가 실행되었다고 결과가 맞는 것은 아니다.

```text
실행
→ 검증
→ 해석
```

### 5. 분석 결과는 의미 있는 결론으로 연결해야 한다.

```text
숫자
→ 패턴
→ 이유 확인
→ 결론
```

### 6. LLM은 분석을 도와주는 도구다.

```text
질문 설정
코드 설명
오류 분석
결과 해석
보고서 작성 보조
```

단, 결과는 직접 검증해야 한다.

### 7. 프로젝트 폴더도 역할별로 나누어 관리한다.

```text
data       → 데이터
notebooks  → 분석 실험
src        → 재사용 코드
scripts    → 실행 스크립트
reports    → 결과물
prompts    → LLM 프롬프트
automation → 자동화
```

## 오늘의 결론

오늘은 데이터 분석에서 가장 중요한 기본 흐름을 다시 정리했다.

데이터 분석은 단순히 Python이나 pandas를 사용하는 작업이 아니라,

```text
무엇이 궁금한지 정하고
→ 필요한 데이터를 이해하고
→ 데이터를 정리하고
→ 분석하고
→ 결과를 검증하고
→ 의미 있는 결론으로 연결하는 과정
```

이라는 점이 핵심이다.

그리고 LLM은 이 과정 전체에서 도움을 줄 수 있지만, 질문을 정하고 결과를 판단하는 역할까지 완전히 대신하는 것은 아니다.

오늘은 이 강의 내용을 바탕으로 실제 데이터 분석 프로젝트를 진행할 수 있도록 GitHub 저장소의 기본 구조까지 만들어 두었다.
