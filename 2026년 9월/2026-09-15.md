# 1. 정규화가 필요한 이유

하나의 큰 테이블에 회원, 도서, 대출 정보를 전부 넣으면 같은 정보가 반복되기 쉽다.

예를 들어 회원 이름이나 도서명이 대출 기록마다 계속 반복되면 수정할 때 여러 행을 동시에 고쳐야 한다.

정규화는 이런 반복을 줄이고 데이터를 역할별 테이블로 나누는 과정이다.

```text
하나의 큰 원본 테이블
↓
회원 정보
도서 정보
대출 정보
↓
각 테이블을 PK/FK로 연결
```

오늘 실습에서는 다음처럼 분리했다.

```text
members_nf
books_nf
loans_nf
```

핵심은 단순히 테이블을 여러 개 만드는 것이 아니라, 각 데이터가 어디에 한 번만 저장되어야 하는지를 결정하는 것이다.

# 2. PK와 FK 다시 정리

## PK

Primary Key는 한 행을 유일하게 식별하는 값이다.

예:

```text
member_id
book_id
loan_id
```

PK는 중복되면 안 되고 보통 NULL도 허용하지 않는다.

## FK

Foreign Key는 다른 테이블의 PK를 참조하는 값이다.

예:

```text
loans_nf.member_id → members_nf.member_id
loans_nf.book_id   → books_nf.book_id
```

즉 대출 정보는 회원과 도서를 직접 중복 저장하는 대신 ID로 연결한다.

# 3. 전체 중복과 키 중복은 다르다

정규화 실습에서 다시 확인한 중요한 포인트다.

```sql
duplicated row
```

과

```text
PK 중복
```

은 같은 문제가 아니다.

또한 FK는 관계에 따라 반복될 수 있다.

예를 들어 한 회원이 여러 번 대출할 수 있으므로 `member_id`가 대출 테이블에서 여러 번 나오는 것은 자연스럽다.

```text
members 1명
↓
loans 여러 건
```

이것이 1:N 관계다.

# 4. 무결성 검증

테이블을 만들고 데이터가 들어갔다고 끝이 아니다.

다음 내용을 확인해야 한다.

```text
PK 중복이 없는가?
FK가 존재하지 않는 값을 참조하지 않는가?
예상 행 수가 맞는가?
JOIN 결과가 이상하게 늘어나지 않는가?
고아 레코드가 없는가?
```

오늘 course project에서도 schema → seed → validation 순서로 확인했다.

```text
스키마 생성
↓
샘플 데이터 입력
↓
관계와 제약조건 검증
```

검증 쿼리를 따로 두는 이유는 '코드가 실행되었다'와 '데이터가 올바르다'가 다른 문제이기 때문이다.

# 5. pandas에서 주문 상세 금액 만들기

Python 실습에서는 주문 상세 데이터에서 금액 컬럼을 만들었다.

```python
order_items["total_price"] = (
    order_items["quantity"] * order_items["unit_price"]
)
```

한 행의 의미는 다음과 같다.

```text
수량 × 단가 = 해당 주문 상세 행의 금액
```

여기서 중요한 점은 모든 주문 상세 금액을 그냥 더한다고 실제 매출이라고 부르면 안 된다는 것이다.

취소 주문 등이 포함되어 있을 수 있기 때문이다.

# 6. merge로 주문 상태 붙이기

`order_items`에는 상품별 상세 정보가 있고, `orders`에는 주문 상태와 고객 정보가 있다.

두 데이터를 연결하기 위해 `merge()`를 사용했다.

```python
merged = order_items.merge(
    orders,
    on="order_id",
    how="left",
    validate="many_to_one"
)
```

여기서 관계는 보통 다음과 같다.

```text
order_items 여러 행
→ 하나의 order_id
→ orders 한 행
```

즉 `many_to_one` 관계다.

`validate="many_to_one"`을 사용하면 예상한 관계가 깨졌을 때 조기에 오류를 확인할 수 있다.

# 7. completed 주문만 필터링

실제 완료 주문 기준으로 집계하려면 주문 상태를 먼저 제한해야 한다.

```python
completed = merged[
    merged["order_status"] == "completed"
].copy()
```

이 단계가 중요한 이유는 분석 범위를 명확히 하기 위해서다.

```text
전체 주문 상세 금액
≠
완료 주문 기준 금액
```

분석 전에 어떤 행을 포함할 것인지 먼저 결정해야 한다.

# 8. 고객별 집계

완료된 주문만 남긴 뒤 고객별로 주문 수와 금액을 계산할 수 있다.

예:

```python
customer_summary = (
    completed
    .groupby("customer_id")
    .agg(
        order_count=("order_id", "nunique"),
        total_amount=("total_price", "sum")
    )
    .reset_index()
)
```

여기서 `nunique()`가 중요한 이유는 주문 상세 행 수와 실제 주문 수가 다르기 때문이다.

```text
주문 1건
상품 3종
→ order_items는 3행
→ 실제 주문 수는 1건
```

따라서 주문 수는 `count()`보다 `order_id.nunique()`가 더 적절할 수 있다.

# 9. SQL과 pandas의 공통점

오늘 실습을 하면서 SQL과 pandas가 방식은 달라도 생각하는 순서는 비슷하다는 점을 확인했다.

```text
데이터 구조 확인
↓
관계 이해
↓
필요한 데이터 연결
↓
분석 범위 정의
↓
집계
↓
검증
```

SQL에서는 PK/FK와 JOIN을 주로 사용하고, pandas에서는 `merge`, `groupby`, `agg`를 사용하지만 목적은 비슷하다.
