Kiwi를 사용하면 문장을 형태소 단위로 나눌 수 있다.

# 3. 토큰 필터링

형태소 분석 결과를 그대로 전부 사용하는 것이 항상 좋은 것은 아니다.

다음과 같은 값은 제거 후보가 될 수 있다.

```text

```

예를 들어:

```python

```

처럼 짧은 토큰을 제거할 수 있다.

하지만 너무 많이 제거하면 오히려 중요한 정보까지 사라질 수 있으므로 결과를 비교하면서 판단해야 한다.

# 6. Git push 충돌과 rebase

오늘 GitHub에 push하려고 했을 때 원격 저장소에 더 최신 commit이 있어서 push가 막히는 상황도 있었다.

이럴 때 사용할 수 있는 명령:

```bash

```


그 후 충돌이 없다면 다시 push할 수 있다.

# 7. SQL 트랜잭션

오늘 SQL에서는 트랜잭션 흐름을 직접 실습했다.

핵심은 여러 SQL 작업을 하나의 묶음으로 처리하는 것이다.

기본 구조:

```sql
BEGIN;

UPDATE ...;

INSERT ...;

SELECT ...;

ROLLBACK;
```

# 8. BEGIN의 의미

`BEGIN`을 실행하면 이후 SQL 작업이 하나의 트랜잭션 안에서 실행된다.

```text
BEGIN
↓
여러 작업 수행
↓
COMMIT 또는 ROLLBACK
```

즉 중간 작업을 확인한 뒤 확정하거나 되돌릴 수 있다.

# 9. ROLLBACK

`ROLLBACK`은 트랜잭션 안에서 수행한 변경사항을 되돌린다.

예를 들어:

```sql
BEGIN;

UPDATE courses
SET available_seats = available_seats - 1
WHERE course_id = 302;

INSERT INTO enrollments (...);

ROLLBACK;
```

이렇게 하면 UPDATE와 INSERT가 모두 취소된다.

테스트 데이터를 직접 바꾸어보면서 결과를 검증한 뒤 원래 상태로 돌릴 때 매우 유용하다.

# 10. 트랜잭션에서는 중간 검증이 중요하다

트랜잭션 안에서도 작업 직후 SELECT로 상태를 확인하는 것이 좋다.

```sql
SELECT *
FROM courses
WHERE course_id = 302;
```

그리고 `ROLLBACK` 후 다시 확인한다.

```text
작업 전
↓
BEGIN
↓
UPDATE / INSERT
↓
SELECT로 변경 확인
↓
ROLLBACK
↓
다시 SELECT
↓
원래 상태 복구 확인
```

단순히 ROLLBACK 명령을 실행하는 것보다 실제 복구 여부를 확인하는 과정이 중요하다.

# 13. 데이터 누수 확인

회귀분석에서 매우 중요한 부분이 데이터 누수다.

Target이 `order_total`인데, Target에서 직접 계산된 값이나 미래 정보가 Feature에 포함되면 실제보다 과하게 좋은 성능이 나올 수 있다.

따라서 Feature를 선택할 때 다음 질문을 해야 한다.

```text
이 값은 실제 예측 시점에 알 수 있는가?
이 컬럼이 Target에서 직접 계산된 것은 아닌가?
정답을 사실상 그대로 알려주는 정보는 아닌가?
```

식별자도 모델 입력으로 무조건 넣는 것이 아니라 실제 의미가 있는지 확인해야 한다.

# 14. 시간 순서 기반 데이터 분할

시간 데이터가 포함된 문제에서는 무작위 분할보다 시간 순서를 유지하는 것이 더 적절할 수 있다.

```text
과거 데이터
→ Train

더 최근 데이터
→ Final Test
```

이렇게 해야 실제 운영 환경처럼 과거로 학습하고 미래를 예측하는 구조가 된다.

# 15. TimeSeriesSplit

시간 순서 검증에서는 `TimeSeriesSplit`을 사용할 수 있다.

일반 K-Fold처럼 임의로 섞기보다 과거 데이터로 학습하고 이후 구간으로 검증한다.

개념적으로:

```text
Fold 1
Train: 과거
Valid: 이후

Fold 2
Train: 더 넓은 과거
Valid: 그 다음 구간
```

이 방식은 시간 흐름이 있는 데이터에서 누수를 줄이는 데 도움이 된다.

# 16. DummyRegressor Baseline

모델 성능을 평가할 때는 바로 복잡한 모델끼리 비교하지 않고 아주 단순한 Baseline부터 만든다.

```python
from sklearn.dummy import DummyRegressor
```

DummyRegressor는 평균값처럼 단순한 기준으로 예측한다.

좋은 모델이라면 최소한 이 Baseline보다 의미 있게 좋아야 한다.

```text
복잡한 모델 성능
>
아무 생각 없이 평균값 예측
```

인지 먼저 확인하는 것이다.

# 17. 최종 모델은 Final Test 전에 고정한다

중요한 원칙이다.

```text
Train
↓
Cross Validation
↓
후보 모델 비교
↓
Selected Model 결정
↓
Final Test 1회 평가
```

Final Test 결과를 보고 다시 모델을 계속 바꾸면 Final Test도 사실상 학습에 사용한 것이 된다.

그래서 최종 평가 전에 모델을 고정해야 한다.

# 18. 회귀 평가 지표

오늘 정리한 주요 회귀 지표는 다음과 같다.

## MAE

평균 절대 오차.

```text
실제값과 예측값 차이의 절대값 평균
```

값이 작을수록 좋다.

## RMSE

큰 오차에 더 큰 패널티를 주는 지표다.

값이 작을수록 좋다.

## R²

모델이 데이터의 변동을 얼마나 설명하는지 보는 지표다.

일반적으로 높을수록 좋지만 하나의 지표만으로 모델을 판단하지 않는다.
