# 1. 필터링 결과가 안 나온다고 코드가 틀린 것은 아니다

오늘 실습하면서 숫자 조건을 바꿨더니 어떤 값에서는 결과가 나오고, 다른 값에서는 아무것도 나오지 않는 경우가 있었다.

예를 들어:

```python
df[df["age"] == 30]
```

에서는 결과가 나오는데,

```python
df[df["age"] == 31]
```

에서는 아무것도 나오지 않을 수 있다.

이 경우 가장 먼저 확인해야 할 것은 **실제 데이터에 그 값이 존재하는지**다.

```python
df["age"].value_counts()
```

또는:

```python
sorted(df["age"].dropna().unique())
```

으로 실제 값들을 확인할 수 있다.

즉 결과가 비어 있다고 해서 무조건 코드 오류는 아니다.

# 2. `isin()`은 여러 값 중 하나인지 확인하는 함수

오늘 다시 본 함수다.

```python
df[df["city"].isin(["서울", "부산"])]
```

뜻은 다음과 같다.

```text
city 값이
서울 또는 부산 목록 안에 들어 있으면 True
```

즉 여러 값을 한 번에 비교할 때 편하다.

다음처럼 여러 `==` 조건을 길게 쓰는 대신:

```python
(df["city"] == "서울") | (df["city"] == "부산")
```

다음처럼 쓸 수 있다.

```python
df["city"].isin(["서울", "부산"])
```

반대로 목록에 없는 값만 고르고 싶으면 `~`를 붙인다.

```python
df[~df["city"].isin(["서울", "부산"])]
```

# 3. `isna().sum()`은 결측치를 세는 조합

오늘 다시 헷갈렸던 부분이다.

```python
df.isna().sum()
```

이 코드는 두 단계로 이해하면 된다.

```text
isna()
→ 값이 비어 있으면 True

sum()
→ True를 1처럼 계산해서 개수를 셈
```

예를 들어:

```python
df["age"].isna().sum()
```

은 `age` 컬럼의 결측치 개수를 구한다.

# 4. 문자열(`str`)과 실수형(`float`) 차이

오늘 pandas를 보면서 Python 기본 타입도 다시 정리했다.

```python
"30"
```

은 문자열이다.

```python
30
```

은 정수형 `int`다.

```python
30.0
```

은 실수형 `float`다.

정리하면:

```text
"30"   → str
30     → int
30.0   → float
```

겉보기에는 모두 숫자처럼 보여도 타입은 다르다.

예를 들어 문자열끼리는 계산이 아니라 이어 붙이기가 될 수 있다.

```python
"3" + "0"
```

결과:

```text
"30"
```

반면 숫자는 실제 계산이 된다.

```python
3 + 0
```

결과:

```text
3
```

# 5. 리스트와 딕셔너리 차이

오늘 기본 Python 문법도 다시 복습했다.

## 리스트

```python
menus = ["짜장면", "짬뽕", "탕수육"]
```

여러 값을 **순서대로** 저장한다.

각 값은 위치 번호인 index로 접근한다.

```python
menus[0]
```

결과:

```text
짜장면
```

## 딕셔너리

```python
student = {
    "name": "조조",
    "score": 100,
    "attendance": 100
}
```

딕셔너리는 `key: value` 형태로 저장한다.

```python
student["name"]
```

결과:

```text
조조
```

즉:

```text
리스트
→ 순서 중심

딕셔너리
→ 이름표(key) 중심
```

# 6. 리스트 안에 딕셔너리를 넣으면 여러 사람 정보를 관리할 수 있다

예를 들어:

```python
students = [
    {"name": "조조", "score": 100},
    {"name": "유비", "score": 33},
    {"name": "손권", "score": 64}
]
```

이 구조는:

```text
students
→ 여러 학생이 들어 있는 리스트

각 학생
→ 이름과 점수를 가진 딕셔너리
```

이렇게 이해하면 된다.

pandas의 한 행도 비슷하게 여러 컬럼 값을 가진 하나의 기록이라고 생각하면 이해가 쉬워진다.

# 7. 데이터가 있을 것 같은데 안 나올 때 확인할 것

오늘 실습 중 “값이 분명 있을 것 같은데 결과가 안 나오는” 경우가 여러 번 있었다.

이럴 때 다음을 확인한다.

```python
print(df.columns.tolist())
print(df.dtypes)
print(df.shape)
```

그리고 해당 컬럼의 실제 값도 확인한다.

```python
df["city"].value_counts(dropna=False)
```

문자열 값이라면 공백도 체크한다.

```python
df["city"].astype(str).str.strip().value_counts()
```

가능한 원인:

```text
값 자체가 존재하지 않음
대소문자 차이
앞뒤 공백
문자열/숫자 타입 차이
컬럼명 오타
결측치
조건 범위 오류
```

# 9. Git의 기본 흐름 다시 복습

오늘 작업한 내용을 GitHub에 올리면서 다시 사용한 흐름이다.

```bash
git status
git add .
git commit -m "메시지"
git push
```

각 단계의 의미는 다음과 같다.

```text
git status
→ 현재 변경 상태 확인

git add .
→ 변경 파일을 staging area에 올림

git commit
→ 변경 내용을 하나의 기록으로 저장

git push
→ 원격 GitHub 저장소에 업로드
```

# 10. LF → CRLF 경고는 오류가 아니다

오늘 `git add .` 실행 후 다음과 비슷한 경고가 나왔다.

```text
LF will be replaced by CRLF
```

이건 Git이 파일의 줄바꿈 형식을 다르게 처리할 수 있다는 경고다.

```text
LF
→ Linux/macOS에서 주로 사용

CRLF
→ Windows에서 주로 사용
```

Windows 환경에서는 자주 볼 수 있다.

코드 내용이 깨졌다는 뜻은 아니고, 대부분은 그대로 진행해도 된다.
