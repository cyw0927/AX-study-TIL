# 1. pandas에서는 먼저 데이터의 구조와 분석 범위를 확인해야 한다

오늘 수업의 핵심은 pandas 문법을 많이 외우는 것보다 **분석 질문을 실제 데이터 처리 과정으로 바꾸는 것**이었다.

예를 들어 다음 질문이 있다고 하자.

```text
완료 주문 기준 카테고리별 매출은 얼마인가?
```

이 질문은 바로 `groupby()`부터 하는 것이 아니라 다음 순서로 바꿔야 한다.

```text
order_items에서 수량과 단가 확인
↓
line_total 계산
↓
orders와 병합해서 주문 상태 확인
↓
completed 주문만 선택
↓
products와 병합해서 카테고리 확인
↓
category별 line_total 합계
↓
병합 결과와 합계 검증
```

같은 코드라도 분석 범위가 다르면 결과 의미가 달라진다.

예를 들어 취소·환불 주문이 들어 있는 상태에서 `line_total.sum()`을 계산했다면 그 값을 바로 매출이라고 부르면 안 된다.

# 2. Series와 DataFrame 차이

오늘 다시 헷갈렸던 부분 중 하나다.

```python
customers["city"]
```

위 코드는 컬럼 하나를 선택하므로 **Series**가 나온다.

```python
customers[["city"]]
```

대괄호 안에 리스트를 넣었기 때문에 컬럼이 하나뿐이어도 **DataFrame**이 나온다.

정리하면:

```text
Series
→ 1차원
→ 컬럼 하나의 값들을 다룰 때 많이 사용

DataFrame
→ 2차원 표 구조
→ 여러 컬럼을 선택하거나 병합·저장할 때 사용
```

`[]`와 `[[]]`가 비슷하게 보여도 결과 타입은 다르다.

# 3. 조건식은 True / False를 만든다

예를 들어:

```python
customers["age"] >= 30
```

이 코드를 실행하면 바로 고객 목록이 나오는 것이 아니라 각 행에 대해 `True`, `False`가 만들어진다.

이 결과를 다시 DataFrame에 넣으면 조건에 맞는 행만 남는다.

```python
customers_over_30 = customers[
    customers["age"] >= 30
]
```

이를 Boolean Mask라고 한다.

복합 조건에서는 Python의 `and`, `or`가 아니라 pandas에서는 주로 다음 기호를 사용한다.

```text
&  → 그리고
|  → 또는
~  → 부정
```

예:

```python
customers[
    (customers["age"] >= 30)
    & (customers["city"] == "서울")
]
```

각 조건을 괄호로 묶는 것도 중요하다.

# 4. `isin()`은 여러 값 중 하나인지 확인한다

오늘 실제로 다시 확인했던 함수다.

```python
customers[
    customers["city"].isin(["서울", "부산"])
]
```

뜻은 다음과 같다.

```text
city 값이
서울 또는 부산에 포함되어 있으면 True
```

SQL의 `IN`과 비슷한 역할이라고 생각하면 이해하기 쉽다.

반대로 제외하고 싶으면 `~`를 붙인다.

```python
orders[
    ~orders["order_status"].isin([
        "cancelled",
        "refunded"
    ])
]
```

# 5. `isna().sum()`은 결측치 개수를 센다

오늘 다시 본 코드:

```python
df.isna().sum()
```

순서대로 보면:

```text
isna()
→ 값이 비어 있으면 True

sum()
→ True를 1처럼 계산해서 개수를 셈
```

따라서 컬럼마다 결측치가 몇 개인지 확인할 수 있다.

예:

```python
customers["age"].isna().sum()
```

이 코드는 `age` 컬럼에서 비어 있는 값이 몇 개인지 알려 준다.

# 6. 정렬은 `sort_values()`

가격이 높은 상품부터 보고 싶다면:

```python
products.sort_values(
    "price",
    ascending=False
)
```

```text
ascending=True
→ 오름차순

ascending=False
→ 내림차순
```

Top 10만 보고 싶다면:

```python
products.sort_values(
    "price",
    ascending=False
).head(10)
```

정렬은 데이터 자체의 의미를 바꾸는 것이 아니라 **행이 보이는 순서**를 바꾸는 것이다.

# 7. 작업용 DataFrame은 `.copy()`로 분리

필터링한 결과에 새 컬럼을 추가할 때는 작업용 복사본을 만드는 것이 안전하다.

```python
completed_orders = orders[
    orders["order_status"] == "completed"
].copy()
```

이렇게 하면 원본 `orders`와 작업용 `completed_orders`를 구분할 수 있다.

특히 `SettingWithCopyWarning` 문제를 줄이는 데 도움이 된다.

# 8. 파생 컬럼 `line_total` 만들기

주문상세 한 행의 금액은 다음과 같이 계산할 수 있다.

```python
order_items_work = order_items.copy()

order_items_work["line_total"] = (
    order_items_work["quantity"]
    * order_items_work["unit_price"]
)
```

즉:

```text
line_total = quantity × unit_price
```

여기서 중요한 점은 `line_total` 한 행이 **주문 전체 금액이 아니라 주문 안의 상품 한 항목 금액**이라는 것이다.

한 주문에 상품이 여러 개 들어 있을 수 있으므로 주문 전체 금액과 주문상세 행은 구분해야 한다.

# 9. `value_counts()`, `groupby()`, `agg()`

## value_counts()

값이 몇 번 나타나는지 확인한다.

```python
orders["order_status"].value_counts(
    dropna=False
)
```

주문 상태별 개수를 확인할 때 유용하다.

## groupby()

같은 값을 가진 행을 그룹으로 묶는다.

```python
products.groupby("category")["price"].mean()
```

여기서는 카테고리 하나가 결과 한 행의 기준이 된다.

## agg()

하나의 그룹에서 여러 집계값을 동시에 계산할 수 있다.

```python
products.groupby(
    "category",
    as_index=False
).agg(
    average_price=("price", "mean"),
    minimum_price=("price", "min"),
    maximum_price=("price", "max")
)
```

# 10. `count()`, `size()`, `nunique()`는 다르다

```text
count()
→ 결측값을 제외한 값의 개수

size()
→ 전체 행 수

nunique()
→ 서로 다른 값의 개수
```

특히 주문 분석에서는 이 차이가 중요하다.

```python
len(order_items)
```

이 값은 주문상세 행 수다.

반면 실제 주문 건수를 구하려면:

```python
order_items["order_id"].nunique()
```

를 사용해야 한다.

한 주문에 여러 상품이 포함될 수 있기 때문에 주문상세 행 수와 주문 건수는 같지 않을 수 있다.

# 11. `merge()`로 여러 파일 연결하기

`order_items`에는 수량과 단가는 있지만 주문 상태나 카테고리가 없다.

그래서 분석 목적에 따라 다른 DataFrame과 연결해야 한다.

```python
order_sales = order_items_work.merge(
    orders,
    on="order_id",
    how="left"
)
```

병합 방식은 대표적으로 다음과 같다.

```text
left
→ 왼쪽 데이터 유지

right
→ 오른쪽 데이터 유지

inner
→ 양쪽에 모두 존재하는 키만 유지

outer
→ 양쪽의 모든 키 유지
```

다만 `left merge`라고 해서 행 수가 무조건 유지되는 것은 아니다.

오른쪽 키에 중복이 있으면 왼쪽 한 행이 여러 행과 연결되어 결과 행 수가 늘어날 수 있다.

# 12. 병합은 실행보다 검증이 중요하다

오늘 수업에서 특히 중요했던 부분이다.

```python
order_sales = order_items_work.merge(
    orders_for_merge,
    on="order_id",
    how="left",
    validate="many_to_one",
    indicator="order_match"
)
```

`validate="many_to_one"`은 왼쪽의 `order_id`는 반복될 수 있지만 오른쪽 `orders.order_id`는 고유해야 한다는 관계를 확인한다.

`indicator`를 사용하면 연결 상태도 확인할 수 있다.

```python
order_sales["order_match"].value_counts(
    dropna=False
)
```

정상적인 경우 기대값은 다음과 같다.

```text
병합 전 행 수 = 병합 후 행 수
order_match = 모두 both
```

즉 병합은 단순히 코드가 실행됐다고 끝내면 안 된다.

# 14. 문자열, float, 리스트, 딕셔너리 다시 정리

오늘 pandas를 하다가 기본 Python 자료형도 다시 확인했다.

## 문자열

```python
name = "홍길동"
```

`str`은 문자 데이터를 의미한다.

숫자처럼 보이더라도 따옴표 안에 있으면 문자열이다.

```python
"30"
```

## float

```python
price = 3.14
```

`float`는 소수점이 있는 실수형 숫자다.

```text
30      → int
30.0    → float
"30"    → str
```

겉으로 비슷해 보여도 타입이 다르면 계산이나 비교 결과가 달라질 수 있다.

## 리스트

```python
cities = ["서울", "부산", "대구"]
```

여러 값을 순서대로 저장한다.

## 딕셔너리

```python
student = {
    "name": "조조",
    "score": 100,
    "attendance": 100
}
```

`key: value` 형태로 값을 저장한다.

리스트 안에 딕셔너리를 여러 개 넣으면 여러 사람의 정보를 구조적으로 관리할 수 있다.
