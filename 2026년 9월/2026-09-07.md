# 1. pandas는 문법보다 먼저 “무엇을 분석할지” 정해야 한다

오늘 pandas 내용을 보면서 가장 중요하다고 느낀 점은 코드를 먼저 치는 것이 아니었다.

예를 들어 다음 질문이 있다고 하자.

```text
완료 주문 기준 카테고리별 매출은 얼마인가?
```

이 질문을 바로 코드로 쓰는 것이 아니라 먼저 필요한 데이터를 나눠 생각해야 한다.

```text
order_items
→ 수량(quantity)
→ 실제 판매 단가(unit_price)
→ 주문 번호(order_id)
→ 상품 번호(product_id)

orders
→ 주문 상태(order_status)
→ 주문일(order_date)
→ 고객 번호(customer_id)

products
→ 상품명(product_name)
→ 카테고리(category)
```

그다음 분석 흐름을 정한다.

```text
order_items 확인
→ quantity × unit_price 계산
→ orders 병합
→ completed 주문만 필터링
→ products 병합
→ category별 집계
→ 결과 검증
```

즉 pandas는 단순히 함수 이름을 외우는 것이 아니라 **분석 질문을 데이터 처리 순서로 바꾸는 도구**라고 이해하는 것이 더 중요하다.

# 2. 오늘 가장 헷갈렸던 `[]`와 `[[]]`

오늘 다시 확실히 정리한 부분이다.

```python
customers["city"]
```

이 결과는 **Series**다.

```text
Series
→ 1차원
→ 열 하나를 꺼낸 형태
```

반면 다음은 다르다.

```python
customers[["city"]]
```

이 결과는 **DataFrame**이다.

```text
DataFrame
→ 2차원
→ 열이 하나뿐이어도 표 형태를 유지
```

즉 괄호 모양만 보면 다음처럼 기억할 수 있다.

```text
["city"]
→ 컬럼 이름 하나
→ Series

[["city"]]
→ 컬럼 이름들이 들어 있는 리스트
→ DataFrame
```

여러 열을 선택하면 당연히 DataFrame이 된다.

```python
customers[["customer_id", "gender", "age", "city"]]
```

앞으로 `[]`와 `[[]]`를 보면 단순히 괄호 개수로 외우기보다 **하나의 열을 꺼내는지, 표 형태로 열 목록을 선택하는지** 생각하면 덜 헷갈릴 것 같다.

# 4. 조건식은 True와 False를 만든다

예를 들어 30세 이상 고객을 찾는 조건은 다음과 같다.

```python
customers["age"] >= 30
```

이 식 자체는 각 행에 대해 `True` 또는 `False`를 만든다.

그 결과를 DataFrame에 넣으면 `True`인 행만 남는다.

```python
customers_over_30 = customers[
    customers["age"] >= 30
]
```

이런 방식의 조건 결과를 **Boolean Mask**라고 한다.

즉 흐름은 다음과 같다.

```text
조건 작성
→ True / False 생성
→ True인 행 선택
```

# 5. pandas에서 여러 조건을 사용할 때는 `and`, `or`가 아니다

여기 역시 Python의 일반 조건문과 헷갈리기 쉬운 부분이다.

pandas에서는 다음 기호를 사용한다.

```text
&
→ AND
→ 두 조건을 모두 만족

|
→ OR
→ 두 조건 중 하나 이상 만족

~
→ NOT
→ 조건 반대
```

예를 들어 30세 이상이면서 서울에 사는 고객은 다음과 같다.

```python
customers[
    (customers["age"] >= 30)
    & (customers["city"] == "서울")
]
```

서울 또는 부산 고객은 다음과 같다.

```python
customers[
    (customers["city"] == "서울")
    | (customers["city"] == "부산")
]
```

완료 주문이 아닌 주문은 다음처럼 쓸 수 있다.

```python
orders[
    ~(orders["order_status"] == "completed")
]
```

여러 조건을 연결할 때는 **각 조건을 괄호로 감싼다.**

# 6. 같은 컬럼에서 여러 값을 찾을 때는 `isin()`

서울과 부산에 사는 고객을 찾는다면 `|`를 사용해도 된다.

```python
customers[
    (customers["city"] == "서울")
    | (customers["city"] == "부산")
]
```

하지만 같은 컬럼에 여러 후보값이 있다면 `isin()`이 더 읽기 쉽다.

```python
customers[
    customers["city"].isin(["서울", "부산"])
]
```

취소와 환불을 제외하려면 `~`와 함께 사용할 수 있다.

```python
orders[
    ~orders["order_status"].isin(
        ["cancelled", "refunded"]
    )
]
```

즉 SQL의 `IN`과도 상당히 비슷한 역할을 한다.

# 7. `sort_values()`로 정렬하기

가격이 높은 상품부터 보고 싶다면 다음과 같이 쓴다.

```python
products.sort_values(
    "price",
    ascending=False
).head(10)
```

```text
ascending=True
→ 오름차순

ascending=False
→ 내림차순
```

여러 기준을 동시에 줄 수도 있다.

```python
products.sort_values(
    ["category", "price"],
    ascending=[True, False]
)
```

이 경우에는 다음 순서로 정렬된다.

```text
1. category 오름차순
2. 같은 category 안에서는 price 내림차순
```

정렬은 데이터를 삭제하거나 계산 결과를 변경하는 것이 아니라 **행을 보여 주는 순서를 바꾸는 작업**이다.

# 8. `.copy()`를 왜 쓰는가

필터링한 DataFrame을 따로 작업할 때 다음처럼 `.copy()`를 붙일 수 있다.

```python
completed_orders = orders[
    orders["order_status"] == "completed"
].copy()
```

이렇게 하면 원본과 작업용 데이터를 구분하기 쉬워진다.

특히 이후 새 컬럼을 추가할 때 예상하지 못한 원본 변경이나 `SettingWithCopyWarning` 가능성을 줄일 수 있다.

```text
원본 데이터
→ orders

분석용 복사본
→ completed_orders
```

원본을 보존한 채 가공한다는 생각으로 이해하면 된다.

# 9. 파생 컬럼 만들기 - `line_total`

주문 상세 데이터에서 한 상품 항목의 금액은 다음처럼 계산할 수 있다.

```python
order_items_work = order_items.copy()

order_items_work["line_total"] = (
    order_items_work["quantity"]
    * order_items_work["unit_price"]
)
```

공식은 단순하다.

```text
line_total
= quantity × unit_price
```

중요한 점은 `line_total`이 **주문 전체 금액이 아니라 주문 상세 한 행의 금액**이라는 것이다.

예를 들어 한 주문에 상품이 세 종류 들어 있다면 같은 `order_id`를 가진 행이 세 개 있을 수 있다.

따라서 다음 두 개는 다른 개념이다.

```text
len(order_items)
→ 주문상세 행 개수
→ 상품 항목 수에 가까움

order_items["order_id"].nunique()
→ 실제 고유 주문 수
```

이 차이를 잘못 이해하면 주문 건수를 크게 잘못 계산할 수 있다.

# 10. 전체 주문 금액과 실제 완료 매출은 다르다

다음 코드를 바로 매출이라고 부르면 위험하다.

```python
order_items_work["line_total"].sum()
```

왜냐하면 아직 주문 상태를 연결하지 않았기 때문이다.

여기에는 다음 주문들이 모두 섞여 있을 수 있다.

```text
completed
cancelled
refunded
```

따라서 상태를 연결하기 전에는 단순히 **전체 주문상세 금액**이라고 보는 것이 안전하다.

실제 완료 주문 기준 매출을 보려면 다음 순서가 필요하다.

```text
order_items
→ orders 병합
→ order_status 확인
→ completed만 선택
→ line_total 합계
```

분석에서는 계산식만 맞는 것이 아니라 **어떤 데이터 범위를 계산했는지**도 중요하다.

# 11. `value_counts()`, `groupby()`, `agg()`

## `value_counts()`

한 컬럼에서 각 값이 몇 번 등장하는지 확인할 때 사용한다.

```python
orders["order_status"].value_counts(dropna=False)
```

예를 들어 다음처럼 주문 상태별 개수를 볼 수 있다.

```text
completed
cancelled
refunded
```

비율로 확인하려면 `normalize=True`를 사용할 수 있다.

```python
orders["payment_method"].value_counts(
    normalize=True,
    dropna=False
).mul(100).round(1)
```

## `groupby()`

어떤 기준으로 데이터를 묶을지 정한다.

```python
products.groupby("category")["price"].mean()
```

`category`로 묶었으므로 결과의 한 행은 **카테고리 하나**를 의미한다.

```text
groupby("category")
→ 결과 한 행 = 카테고리 하나

groupby("customer_id")
→ 결과 한 행 = 고객 한 명

groupby("order_month")
→ 결과 한 행 = 한 달
```

즉 `groupby()`의 기준은 결과표에서 **한 행의 의미를 결정한다.**

## `agg()`

한 번에 여러 집계값을 만들 수 있다.

```python
category_price_summary = (
    products
    .groupby("category", as_index=False)
    .agg(
        product_count=("product_id", "nunique"),
        average_price=("price", "mean"),
        minimum_price=("price", "min"),
        maximum_price=("price", "max"),
    )
)
```

한 번의 그룹화로 개수, 평균, 최소값, 최대값을 같이 계산할 수 있다.

# 12. `count()`, `size()`, `nunique()`는 서로 다르다

이 세 개도 이름이 비슷해서 헷갈리기 쉽다.

```text
count()
→ 결측값을 제외한 값의 개수

size()
→ 그룹에 들어 있는 전체 행 수

nunique()
→ 서로 다른 고유값의 개수
```

특히 주문 데이터에서는 `nunique()`가 중요하다.

```python
order_count = order_items["order_id"].nunique()
```

주문 하나에 여러 상품이 있을 수 있기 때문에 단순히 행 개수를 세면 실제 주문 건수와 달라진다.

# 13. `merge()`는 SQL의 JOIN과 비슷하다

`order_items`만으로는 주문 상태를 알 수 없다.

그래서 `orders`와 연결한다.

```python
order_items.merge(
    orders,
    on="order_id",
    how="left"
)
```

상품 카테고리를 알고 싶다면 `products`도 연결한다.

```python
order_items.merge(
    products,
    on="product_id",
    how="left"
)
```

주요 병합 방식은 다음과 같다.

```text
left
→ 왼쪽 데이터는 모두 유지

right
→ 오른쪽 데이터는 모두 유지

inner
→ 양쪽에 모두 있는 키만 유지

outer
→ 양쪽의 모든 키 유지
```

다만 `left`라고 해서 무조건 행 수가 그대로 유지되는 것은 아니다.

오른쪽 테이블의 키가 중복되어 있으면 왼쪽 한 행이 여러 행과 연결되면서 행 수가 늘어날 수 있다.

# 14. 일대일, 일대다, 다대일, 다대다 관계

병합 전에 키 관계를 알아야 한다.

```text
1 : 1
→ 양쪽 키 모두 고유

1 : N
→ 왼쪽 키는 고유, 오른쪽 키는 반복

N : 1
→ 왼쪽 키는 반복, 오른쪽 키는 고유

N : M
→ 양쪽 키 모두 반복
```

쇼핑몰 예제에서는 다음 관계가 중요하다.

```text
order_items.order_id
→ orders.order_id
→ many_to_one
```

왜냐하면 하나의 주문에는 여러 상품 상세 행이 존재할 수 있지만 `orders`에서는 `order_id` 하나가 주문 한 건을 의미하기 때문이다.

상품도 비슷하다.

```text
order_items.product_id
→ products.product_id
→ many_to_one
```

하나의 상품은 여러 주문 상세에서 반복될 수 있지만 상품 마스터에서는 `product_id`가 하나의 상품을 가리킨다.

# 15. `validate`와 `indicator`로 병합을 검증한다

병합 코드가 실행됐다고 해서 병합이 올바른 것은 아니다.

관계가 `many_to_one`이라고 예상한다면 다음처럼 명시할 수 있다.

```python
order_sales = order_items_work.merge(
    orders[
        [
            "order_id",
            "customer_id",
            "order_date",
            "order_status",
        ]
    ],
    on="order_id",
    how="left",
    validate="many_to_one",
)
```

오른쪽 `orders.order_id`가 중복되어 있다면 오류가 발생하기 때문에 잘못된 병합을 빨리 찾을 수 있다.

`indicator`도 사용할 수 있다.

```python
order_sales = order_items_work.merge(
    orders,
    on="order_id",
    how="left",
    validate="many_to_one",
    indicator="order_match",
)
```

그다음 다음을 확인한다.

```python
order_sales["order_match"].value_counts(dropna=False)
```

정상적으로 연결됐다면 대부분 또는 전부 `both`여야 한다.

```text
both
→ 양쪽에서 모두 찾음

left_only
→ 왼쪽에는 있는데 오른쪽에서 연결할 값을 찾지 못함
```

또 병합 전후 행 수도 확인한다.

```python
print(len(order_items_work))
print(len(order_sales))
```

다대일 병합을 예상했다면 일반적으로 행 수가 유지되어야 한다.

# 16. pandas 분석 전체 흐름 다시 정리

오늘 내용을 하나로 연결하면 다음과 같다.

```text
분석 질문 정하기
        ↓
필요한 파일과 컬럼 확인
        ↓
Series / DataFrame으로 컬럼 선택
        ↓
조건 필터링
        ↓
정렬
        ↓
파생 컬럼 생성
        ↓
필요한 DataFrame 병합
        ↓
분석 범위 확정
        ↓
groupby / agg 집계
        ↓
병합 결과와 합계 검증
        ↓
CSV 저장
```

중요한 것은 **코드가 실행됐는가가 아니라 결과가 질문에 제대로 답하고 있는가**이다.

# 17. PostgreSQL에서 CRUD 다시 정리

오늘 SQL에서는 가장 기본인 CRUD를 공부했다.

| CRUD | SQL | 의미 |
| --- | --- | --- |
| Create | `INSERT` | 새로운 데이터 추가 |
| Read | `SELECT` | 데이터 조회 |
| Update | `UPDATE` | 기존 데이터 수정 |
| Delete | `DELETE` | 기존 데이터 삭제 |

여기서 헷갈릴 수 있는 점이 하나 있다.

```text
CRUD의 Create
→ INSERT

CREATE TABLE
→ 데이터를 넣는 것이 아니라 데이터를 저장할 구조를 만드는 것
```

즉 `CREATE TABLE`의 CREATE와 CRUD의 Create는 같은 의미로 대응시키면 안 된다.

# 19. `CREATE TABLE`로 students 테이블 만들기

예제에서는 다음과 같이 테이블을 생성했다.

```sql
CREATE TABLE public.students (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    major VARCHAR(100),
    grade INTEGER,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

주요 요소를 정리하면 다음과 같다.

```text
PRIMARY KEY
→ 한 행을 고유하게 구분

NOT NULL
→ 최종 저장값으로 NULL 허용 안 함

UNIQUE
→ 같은 값 중복 제한

DEFAULT
→ 값을 생략했을 때 기본값 사용

IDENTITY
→ 번호 자동 생성

TIMESTAMPTZ
→ 날짜와 시각 저장
```

`major`, `grade`에는 `NOT NULL`이 없으므로 값이 없으면 `NULL`이 들어갈 수 있다.

# 21. `SELECT`는 데이터를 조회한다

모든 열을 조회한다.

```sql
SELECT *
FROM public.students;
```

필요한 열만 고를 수도 있다.

```sql
SELECT id, name, email, major
FROM public.students
ORDER BY id ASC;
```

가능하면 분석할 때와 마찬가지로 필요한 열만 선택하는 것이 결과를 이해하기 쉽다.

```sql

    name AS student_name,
    major AS student_major
FROM public.students;
```

# 22. `WHERE`로 필요한 행만 고른다

컴퓨터공학 전공만 조회하려면 다음과 같다.

```sql
SELECT *
FROM public.students
WHERE major = '컴퓨터공학'
ORDER BY id ASC;
```

3학년 이상만 조회하려면 다음과 같다.

```sql
SELECT id, name, grade
FROM public.students
WHERE grade >= 3
ORDER BY grade DESC, id ASC;
```

Python에서는 같은지 비교할 때 `==`를 사용했지만 SQL에서는 `=`을 사용한다.

```text
Python
==

SQL
=
```

# 23. SQL의 `AND`, `OR`, `IN`

모든 조건을 만족해야 할 때 `AND`를 사용한다.

```sql
SELECT *
FROM public.students
WHERE major = '컴퓨터공학'
  AND grade >= 3;
```

하나 이상 만족하면 `OR`를 사용한다.

```sql
SELECT *
FROM public.students
WHERE major = '컴퓨터공학'
   OR major = '데이터사이언스';
```

같은 컬럼을 여러 값과 비교한다면 `IN`이 읽기 쉽다.

```sql
SELECT *
FROM public.students
WHERE major IN ('컴퓨터공학', '데이터사이언스');
```

pandas의 `isin()`과 대응해서 생각하면 이해하기 쉽다.

```text
pandas
Series.isin([...])

SQL
IN (...)
```

# 24. `LIKE`로 문자열 패턴 검색

이름이 김으로 시작하는 학생을 찾는다.

```sql
SELECT *
FROM public.students
WHERE name LIKE '김%';
```

패턴은 다음과 같다.

```text
'김%'
→ 김으로 시작

'%민%'
→ 중간에 민 포함

'%우'
→ 우로 끝남

'김__'
→ 김 뒤에 정확히 두 문자
```

```text
%
→ 0개 이상의 문자

_
→ 정확히 한 문자
```

PostgreSQL에서는 대소문자를 구분하지 않는 검색에 `ILIKE`도 사용할 수 있다.

# 25. SQL에서 `NULL`은 `= NULL`로 찾으면 안 된다

오늘 SQL에서 매우 중요한 부분이다.

다음 코드는 원하는 결과가 나오지 않는다.

```sql
SELECT *
FROM public.students
WHERE major = NULL;
```

`NULL`은 일반 값이 아니라 **값이 없거나 아직 알려지지 않은 상태**를 의미한다.

그래서 다음처럼 써야 한다.

```sql
SELECT *
FROM public.students
WHERE major IS NULL;
```

NULL이 아닌 데이터를 찾으려면 다음과 같다.

```sql
SELECT *
FROM public.students
WHERE major IS NOT NULL;
```

즉 기억할 것은 이것이다.

```text
잘못된 방식
= NULL
<> NULL

올바른 방식
IS NULL
IS NOT NULL
```

# 26. `DISTINCT`, `ORDER BY`, `LIMIT`

중복 값을 제거해 전공 목록만 확인하려면 다음과 같다.

```sql
SELECT DISTINCT major
FROM public.students
WHERE major IS NOT NULL
ORDER BY major ASC;
```

`DISTINCT`는 원본 데이터의 중복을 삭제하는 것이 아니라 **조회 결과에서 중복된 값을 제거한다.**

결과의 순서를 정하려면 `ORDER BY`를 사용한다.

```sql
SELECT *
FROM public.students
ORDER BY grade ASC, id ASC;
```

가져올 행 수를 제한하려면 `LIMIT`을 사용한다.

```sql
SELECT *
FROM public.students
ORDER BY created_at DESC, id DESC
LIMIT 3;
```

`LIMIT 3`만 보고 최근 3개라고 생각하면 안 된다.

먼저 `ORDER BY`로 어떤 순서를 만들었는지가 중요하다.

# 27. `UPDATE`는 무조건 먼저 대상을 조회한다

예를 들어 이준호의 학년을 4로 변경한다고 하자.

바로 `UPDATE`부터 실행하지 않고 먼저 대상을 확인한다.

```sql
SELECT *
FROM public.students
WHERE email = 'junho@example.com';
```

그다음 수정한다.

```sql
UPDATE public.students
SET grade = 4
WHERE email = 'junho@example.com'
RETURNING id, name, grade;
```

그리고 다시 확인한다.

```sql
SELECT *
FROM public.students
WHERE email = 'junho@example.com';
```

정리하면 다음과 같다.

```text
SELECT로 대상 확인
→ UPDATE 실행
→ 영향받은 행 확인
→ SELECT로 다시 검증
```

가장 위험한 것은 `WHERE`를 빼먹는 것이다.

```sql
UPDATE public.students
SET grade = 1;
```

이 코드는 문법 오류가 아니다.

**모든 학생의 grade를 1로 변경한다.**

SQL에서는 문법적으로 맞는 코드가 업무적으로는 큰 사고가 될 수 있다.

# 28. `DELETE`도 같은 원칙을 사용한다

데이터 삭제도 바로 실행하지 않는다.

먼저 대상 확인:

```sql
SELECT *
FROM public.students
WHERE email = 'seoyeon@example.com';
```

그다음 삭제:

```sql
DELETE FROM public.students
WHERE email = 'seoyeon@example.com'
RETURNING id, name, email;
```

그리고 다시 조회해 실제로 사라졌는지 확인한다.

```text
SELECT로 삭제 대상 확인
→ DELETE 실행
→ 영향받은 행 확인
→ SELECT로 결과 검증
```

`DELETE` 역시 `WHERE`가 없으면 전체 행을 삭제할 수 있으므로 특히 주의해야 한다.

# 29. pandas와 SQL을 같이 보니 비슷한 점이 많았다

오늘 두 내용을 같이 공부하니 서로 대응되는 개념이 꽤 많았다.

| pandas | SQL | 역할 |
| --- | --- | --- |
| `df[["a", "b"]]` | `SELECT a, b` | 필요한 열 선택 |
| Boolean Mask | `WHERE` | 필요한 행 선택 |
| `&` | `AND` | 모든 조건 만족 |
| `|` | `OR` | 하나 이상 만족 |
| `isin()` | `IN` | 여러 후보값 중 하나 |
| `sort_values()` | `ORDER BY` | 정렬 |
| `merge()` | `JOIN` | 데이터 연결 |
| `groupby()` | `GROUP BY` | 그룹별 집계 |
| `isna()` | `IS NULL` | 결측/NULL 확인 |

문법은 다르지만 결국 둘 다 다음 작업을 한다.

```text
어떤 데이터를 볼 것인가?
어떤 행을 남길 것인가?
어떻게 정렬할 것인가?
어떻게 연결할 것인가?
어떤 기준으로 요약할 것인가?
```

pandas는 Python 안에서 DataFrame을 다루고, SQL은 DBMS에 저장된 테이블을 직접 조회한다는 차이가 있지만 데이터에 질문하는 사고방식은 상당히 비슷하다.

# 32. 오늘 배운 것을 한 문장으로 다시 정리

오늘 배운 pandas와 SQL은 결국 **데이터를 무작정 코드로 처리하는 것이 아니라, 한 행의 의미와 분석 범위를 먼저 정하고 필요한 데이터를 선택·필터링·연결·집계한 뒤 반드시 결과를 검증하는 과정**이었다.

특히 앞으로는 AI가 만들어 준 코드가 오류 없이 실행된다고 끝내지 않고, **실제 컬럼명, 데이터 범위, 키 관계, 행 수, 합계까지 직접 확인하는 습관**을 들여야겠다.
