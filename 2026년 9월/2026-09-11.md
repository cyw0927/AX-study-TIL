# 1. AI가 분석을 대신하는 것이 아니다

오늘 수업에서 가장 중요한 내용 중 하나는 AI의 역할이었다.

AI는 코드를 빠르게 만들어 줄 수 있다.

하지만 다음은 사람이 직접 해야 한다.

```text
무엇을 확인할 것인가?
왜 이 작업이 필요한가?
실행 결과가 실제로 무엇을 보여 주는가?
이 결과를 어떻게 해석할 것인가?
추가 분석이 필요한가?
다음에 무엇을 할 것인가?
```

즉:

```text
AI = 코드 작성 보조
사람 = 분석 방향 결정 + 결과 검증 + 해석
```

코드가 실행됐다고 분석이 끝난 것이 아니다.

# 8. 결측치는 무조건 지우거나 채우지 않는다

Titanic에서는 대표적으로 다음 컬럼에 결측이 있다.

```text
Age
Cabin
Embarked
```

중요한 원칙:

```text
결측치 발견
≠
즉시 삭제 또는 대체
```

먼저 다음을 본다.

```text
결측 비율
컬럼의 의미
다른 정보로 대체 가능한가
정보를 잃어도 되는가
```

탐색용 예시:

```python
age_median = df_work["Age"].median()
embarked_mode = df_work["Embarked"].mode().iloc[0]

_df = df_work["Age"].fillna(age_median)
```

하지만 모델링 단계에서는 전체 데이터를 기준으로 중앙값이나 최빈값을 계산하면 안 된다.

train/test를 나눈 뒤 **train 데이터 기준으로만 전처리 기준을 학습**해야 한다.

# 9. 컬럼은 바로 삭제하지 않고 역할을 판단한다

오늘 새롭게 기억할 분류:

```text
KEEP
→ 그대로 사용 후보

EXCLUDE
→ 모델 입력에서는 제외 후보

DERIVE
→ 새로운 Feature를 만들 재료

DEFER
→ 지금 판단 보류
```

예를 들어:

```text
PassengerId
→ 식별자라서 EXCLUDE 가능

Name
→ Title 추출 가능하므로 DERIVE 가능

Cabin
→ Deck 정보로 DERIVE 가능

Ticket
→ 그룹 정보가 있을 수도 있으므로 DEFER 가능
```

즉 컬럼을 단순히 "필요 없어 보인다"는 이유로 바로 삭제하면 안 된다.

# 10. 범주형 데이터 변환

머신러닝에서는 문자열 범주를 그대로 사용하기 어려운 경우가 많다.

## Mapping

값이 두 종류일 때 단순 변환을 사용할 수 있다.

```python
df_encoded["SexMapped"] = df_encoded["Sex"].map({
    "male": 0,
    "female": 1
})
```

## One-Hot Encoding

순서가 없는 여러 범주는 One-Hot Encoding을 사용할 수 있다.

```python
pd.get_dummies(
    df_encoded["Embarked"],
    prefix="Embarked",
    dtype=int
)
```

`Embarked`에 단순히 0, 1, 2를 넣으면 숫자 크기에 순서가 있는 것처럼 오해될 수 있다.

오늘 핵심은 "무조건 숫자로 바꾼다"가 아니라 **범주의 의미에 맞는 변환 방법을 선택한다**는 것이다.

# 11. 시각화는 그래프보다 질문이 먼저다

그래프를 그릴 때 먼저:

```text
무슨 그래프를 그릴까?
```

라고 생각하는 것이 아니라:

```text
무엇이 궁금한가?
```

를 먼저 정해야 한다.

예:

```text
성별에 따라 생존율이 다른가?
객실 등급에 따라 생존율이 다른가?
나이와 생존 사이에 패턴이 있는가?
Fare와 생존 사이에 차이가 있는가?
```

질문을 정한 다음 알맞은 그래프를 선택한다.

```text
질문
↓
그래프 선택
↓
실행
↓
관찰
↓
해석
↓
다음 질문
```

# 12. 관찰과 해석을 구분해야 한다

예를 들어 여성 생존율이 높게 나왔다고 해도:

```text
여성이기 때문에 생존했다
```

라고 바로 쓰면 안 된다.

더 적절한 표현:

```text
여성 승객 집단에서 더 높은 생존율이 관찰되었다.
```

정리하면:

```text
관찰
→ 데이터에서 직접 확인한 사실

해석
→ 그 사실이 어떤 의미를 가질 수 있는지 설명

가설
→ 가능한 원인

한계
→ 현재 데이터만으로 확정할 수 없는 부분
```

상관이나 집단 차이를 바로 인과관계로 해석하면 안 된다.

# 13. groupby로 그래프 결과를 숫자로 다시 확인

시각화에서 본 패턴은 통계로 다시 확인한다.

예:

```python
sex_count = df_work.groupby("Sex").size()
sex_survival_rate = df_work.groupby("Sex")["Survived"].mean()
```

Pclass, Embarked 등도 같은 방식으로 확인할 수 있다.

```python
df_work.groupby("Pclass")["Survived"].mean()
```

시각화와 수치를 같이 보면 결과를 더 명확하게 이해할 수 있다.

# 14. Feature Engineering

EDA에서 찾은 패턴을 모델이 사용할 수 있는 새로운 입력 정보로 바꿀 수 있다.

예:

```python
feature_demo["FamilySize"] = (
    feature_demo["SibSp"]
    + feature_demo["Parch"]
    + 1
)
```

그리고:

```python
feature_demo["IsAlone"] = (
    feature_demo["FamilySize"] == 1
).astype(int)
```

## Feature는 두 종류로 구분

```text
결정적 Feature
→ 한 행만 보고 항상 같은 결과 생성

예:
FamilySize
IsAlone
Title
Deck
```

반면:

```text
데이터에서 기준을 학습하는 Feature
→ 전체 분포나 통계가 필요

예:
qcut
빈도 기반 Rare category
평균/중앙값 기반 변환
Target Encoding
```

후자의 경우 반드시 train 데이터 기준으로 만들어야 한다.
