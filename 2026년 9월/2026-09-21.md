오늘의 핵심은 단순히 코드를 많이 추가하는 것이 아니었다.

기존 Notebook을 보면서 다음 질문에 답할 수 있도록 만드는 것이 목적이었다.

```text
이 실습은 무엇을 확인하려는가?
왜 이 코드를 실행하는가?
실행 결과에서 무엇을 봐야 하는가?
결과가 예상과 다르면 어디를 확인해야 하는가?
```

즉 Notebook을 단순 실행 파일이 아니라 **나중에 다시 봐도 이해할 수 있는 학습 자료**로 만드는 작업이었다.

# 2. git pull로 최신 작업 받아오기

오늘은 로컬 폴더에서 GitHub의 최신 내용을 받아오는 흐름을 다시 사용했다.

작업 위치:

```text
C:\dev\llm-data-analysis-course
```

기본 흐름:

```bash
git pull
```

`git pull`은 원격 저장소의 최신 변경사항을 현재 로컬 저장소에 가져와 반영한다.

쉽게 말하면:

```text
GitHub에 최신 버전 존재
↓
git pull
↓
내 컴퓨터 작업 폴더도 최신 상태로 맞춤
```

다른 환경이나 다른 작업 흐름에서 수정된 파일을 다시 로컬에서 이어서 작업할 때 특히 중요하다.

예를 들어:

```text

```

이 셋이 서로 다른 환경을 보고 있으면 터미널에서는 설치했다고 나오는데 Notebook에서는 `ModuleNotFoundError`가 발생할 수 있다.

# 4. 패키지는 '어디에 설치했는가'가 중요하다

패키지 설치 자체보다 중요한 것은 현재 실행 중인 Python에 설치되었는지 확인하는 것이다.

확인할 때는 다음처럼 볼 수 있다.

```python
import sys

print(sys.executable)
print(sys.version)
```

현재 Notebook이 실제로 어떤 Python을 사용하고 있는지 먼저 확인한 뒤 패키지를 설치하는 습관이 필요하다.

오늘은 Python 3.12 환경에서 `scikit-learn` 설치를 완료하고 Chapter 03 실습을 이어갈 수 있게 만들었다.

# 5. Notebook을 자세히 작성한 이유

처음 공부할 때 Notebook에 코드만 있으면 실행할 때는 넘어갈 수 있어도 며칠 뒤 다시 보면 기억이 잘 나지 않는다.

예를 들어 이런 식으로 코드만 있으면:

```python
result = some_function(data)
result
```

나중에는 다음이 다시 궁금해진다.

```text
some_function이 뭐였지?
왜 이 데이터를 넣었지?
결과 숫자는 무엇을 뜻하지?
이게 정상 결과인가?
```

그래서 오늘은 코드 주변의 Markdown 설명을 훨씬 자세히 작성했다.

# 6. 좋은 Notebook 구조

오늘 정리한 방식은 대략 다음 흐름이다.

```text
실습 제목
↓
이번 실습의 목적
↓
먼저 알아야 할 개념
↓
실행 코드
↓
실행 결과 확인
↓
결과 해석
↓
추가 검증
↓
주의할 점
```

이렇게 하면 단순히 코드를 복사해서 실행하는 것보다 훨씬 복습하기 쉽다.

# 7. 검증 코드가 필요한 이유

코드가 오류 없이 실행되었다고 해서 항상 올바른 결과가 나온 것은 아니다.

그래서 본 코드 뒤에 검증 코드를 추가하는 방식이 중요하다.

예를 들어 데이터 분석이라면 다음처럼 확인할 수 있다.

```python
print(df.shape)
print(df.columns)
print(df.dtypes)
print(df.isna().sum())
```

즉,

```text
코드 실행 성공
≠
결과가 올바름
```

이다.

실행 후 데이터 크기, 자료형, 결측치, 범주, 값의 범위 등을 직접 확인해야 한다.

# 8. 코드를 한꺼번에 보지 않고 단계별로 보기

긴 코드는 처음부터 한 덩어리로 보면 이해하기 어렵다.

오늘 Notebook을 확장하면서도 다음처럼 나눠서 보는 방식이 중요했다.

```text
1. 데이터 준비
2. 필요한 컬럼 선택
3. 변환
4. 계산
5. 결과 확인
6. 검증
```

각 단계가 무엇을 입력받고 무엇을 만드는지 확인하면 긴 코드도 훨씬 이해하기 쉬워진다.

# 9. Markdown 셀의 역할

Jupyter Notebook에서 Markdown 셀은 단순한 꾸미기가 아니다.

코드의 이유와 결과를 설명하는 문서 역할을 한다.

예를 들어 다음 항목을 적어두면 좋다.

```markdown
## 실습 목적

이 단계에서는 무엇을 확인한다.

## 코드 설명

각 줄이 어떤 역할을 하는지 정리한다.

## 실행 결과

실제 출력에서 어떤 값을 확인했는지 적는다.

## 해석

그 결과가 무엇을 의미하는지 내 말로 적는다.

## 주의점

결과를 해석할 때 조심할 부분을 적는다.
```

이 구조를 반복하면 Notebook 자체가 하나의 교재가 된다.

# 12. 오늘 다시 확인한 Git 개념

## git pull

원격 저장소의 최신 변경사항을 받아 현재 로컬 브랜치에 반영한다.

```bash
git pull
```

## git status

현재 변경된 파일이 무엇인지 확인한다.

```bash
git status
```

## git add

커밋할 변경사항을 스테이징한다.

```bash
git add .
```

## git commit

변경사항을 하나의 기록으로 만든다.

```bash
git commit -m "message"
```

## git push

내 로컬 커밋을 원격 GitHub에 올린다.

```bash
git push
```

전체 흐름은 다음처럼 기억하면 된다.

```text
pull
→ 작업
→ status
→ add
→ commit
→ push
```
