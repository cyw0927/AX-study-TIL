## 1. 익명화 평가 데이터의 동명이인 처리

원본 CSV를 확인하면서 이름만 중복 제거하면 24명이지만, 같은 별칭이 서로 다른 팀에 등장하는 사례가 있다는 점을 확인했다.

따라서 이름만으로 사용자를 식별하지 않고 `별칭 + 소속 팀`을 기준으로 학생 엔티티를 분리했다. 이 기준을 적용하면 총 28명의 학생으로 해석된다.

핵심은 원본 데이터를 임의로 수정하는 것이 아니라, 원본은 그대로 보존하고 시스템 내부에서 식별 규칙을 별도로 적용하는 것이다.

## 2. 평가 제출 현황과 데이터 정합성 점검

평가 원본 행 수를 그대로 제출 완료 수로 취급하면 실제 미제출자가 사라지는 문제가 있었다.

그래서 평가 진행률은 원본 CSV 행 개수가 아니라 실제로 제출 가능한 `평가자-평가 대상` 조합을 기준으로 계산하도록 정리했다.

현재 기준으로 확인한 값은 다음과 같다.

- 전체 수강생: 28명
- 팀 평가 제출: 63 / 84
- 개인 평가 제출: 99 / 174
- 전체 미제출: 96건
- 원본 응답: 개인 101건 + 팀 66건 보존

데이터를 점검할 수 있도록 별도의 audit 명령도 추가했다.

```bash
python manage.py audit_ax2_consistency
```

이 과정을 통해 **원본 데이터 수와 실제 업무상 유효한 제출 수는 다를 수 있다**는 점을 확인했다.

## 3. 회원가입 기능 추가

기존 시스템은 Google/Kakao 로그인과 관리자 생성 계정 중심이라, 관리자가 수강생 계정을 일일이 만들어야 하는 문제가 있었다.

이를 개선하기 위해 수강생이 직접 아이디와 비밀번호를 만드는 일반 회원가입 기능을 추가했다.

회원가입 시 다음 항목을 입력한다.

- 아이디
- 이름
- 이메일(선택)
- 비밀번호
- 비밀번호 확인

가입과 동시에 Django `User`와 `Student` 프로필이 함께 생성되고 학생 권한으로 로그인된다.

Google/Kakao 로그인은 기존 방식 그대로 유지한다.

## 4. Django 인증 백엔드 오류 해결

회원가입 직후 로그인 과정에서 다음 오류가 발생했다.

```text
ValueError: You have multiple authentication backends configured
```

현재 프로젝트는 Django 기본 인증과 django-allauth 인증을 동시에 사용하기 때문에, 새로 만든 일반 계정을 `login()`할 때 어떤 backend를 사용할지 명시해야 했다.

```python
login(
    request,
    user,
    backend="django.contrib.auth.backends.ModelBackend",
)
```

일반 아이디/비밀번호 로그인은 Django `ModelBackend`, Google/Kakao 로그인은 allauth가 담당하도록 역할을 분리했다.

## 5. 테스트를 통해 기존 기능 오류 수정

Django 테스트를 반복 실행하면서 실제 화면에서는 잘 보이지 않던 문제들을 발견했다.

### 과제 제출 assignment_id 오류

기존 테스트 요청에서 `assignment_id`가 빠지면 빈 문자열이 PK 조회에 들어가면서 오류가 발생했다.

```text
Field 'id' expected a number but got ''
```

과제가 하나뿐인 경우에는 안전하게 해당 과제를 식별할 수 있도록 호환 처리를 추가했다.

### 첨부파일 다운로드 파일명 문제

Django 저장소에서 같은 파일명이 존재하면 파일명 뒤에 임의 문자열이 붙을 수 있다.

예:

```text
guide.txt
→ guide_1Hh1V5z.txt
```

실제 사용자 다운로드 시에는 원래 파일명이 보이도록 보정했다.

## 오늘 배운 점

데이터를 다룰 때 단순히 `DISTINCT 이름`이나 원본 행 개수만 믿으면 실제 업무 규칙과 다른 결과가 나올 수 있다.

특히 사용자 식별, 평가 미제출, 중복 응답처럼 현실 데이터에서 자주 발생하는 예외는 원본을 보존한 상태에서 별도의 식별 및 검증 규칙을 두는 것이 중요하다.

또한 화면이 정상적으로 동작해 보여도 테스트를 실행하면 인증 backend, 빈 PK, 파일명 충돌 같은 예외 상황을 발견할 수 있었다.

오늘 가장 크게 느낀 점은 **기능 구현 자체보다 데이터 기준을 하나로 통일하는 것이 더 중요하다**는 것이다. 화면마다 다른 기준을 사용하면 숫자가 조금씩 달라지고 결국 시스템 전체 신뢰도가 떨어진다.
