# 1. AI는 갑자기 등장한 기술이 아니다

최근에는 ChatGPT와 같은 생성형 AI 때문에 AI가 갑자기 등장한 것처럼 느껴지지만, 실제로는 오랜 기간 여러 번의 발전과 침체를 거쳐 왔다.

간단히 흐름을 정리하면 다음과 같다.

```text
1950년대
→ 기계가 인간처럼 생각할 수 있는가?
→ 튜링 테스트, 초기 인공지능 연구

1956년
→ 다트머스 회의
→ Artificial Intelligence라는 연구 분야가 본격적으로 자리 잡음

1970~1980년대
→ 규칙을 사람이 직접 입력하는 전문가 시스템 발전

1990~2000년대
→ 데이터와 통계적 방법을 활용하는 머신러닝이 발전

2010년대
→ GPU와 대규모 데이터의 발전
→ 딥러닝 성능이 크게 향상

2017년 이후
→ Transformer 구조 등장
→ 대규모 언어 모델 발전

2020년대
→ 생성형 AI와 LLM이 일반 사용자에게 빠르게 확산
```

즉, 현재의 생성형 AI도 이전의 머신러닝과 딥러닝 연구가 계속 쌓인 결과라고 볼 수 있다.

# 2. 튜링 테스트란 무엇인가

앨런 튜링은 1950년에 기계가 지능을 가지고 있는지를 직접 정의하는 대신, **사람과 대화했을 때 인간인지 기계인지 구별하기 어려운가**라는 방식으로 문제를 바꾸어 생각했다.

개념을 단순화하면 다음과 같다.

```text
사람 A ─┐
        ├─ 문자 대화 → 판정자
기계 B ─┘

판정자가 대화 상대가 사람인지 기계인지 안정적으로 구별하지 못한다면
기계가 인간과 비슷한 대화 능력을 보였다고 볼 수 있다.
```

### 중요한 점

튜링 테스트는 기계의 모든 지능을 완벽하게 측정하는 시험은 아니다.

예를 들어 어떤 AI가 매우 자연스럽게 말한다고 해서 반드시 다음 능력을 모두 가지고 있는 것은 아니다.

- 세상을 인간처럼 이해하는 능력
- 사실을 항상 정확하게 판단하는 능력
- 감정이나 자아를 실제로 가지는 것
- 논리 문제를 항상 정확하게 푸는 능력

따라서 **대화를 잘한다 = 모든 면에서 인간 수준의 지능을 가진다**라고 바로 결론 내리면 안 된다.

# 3. 머신러닝이란 무엇인가

기존 프로그래밍에서는 사람이 규칙을 직접 코드로 작성한다.

예를 들어 시험 점수가 60점 이상이면 합격이라고 한다면 다음처럼 사람이 규칙을 작성한다.

```python
score = 75

if score >= 60:
    print("합격")
else:
    print("불합격")
```

구조를 정리하면 다음과 같다.

```text
데이터 + 사람이 만든 규칙
        ↓
      결과
```

머신러닝은 조금 다르다.

사람이 모든 규칙을 직접 작성하기 어려운 문제에서 **많은 데이터와 정답을 주고, 컴퓨터가 데이터 속 패턴을 학습하게 한다.**

```text
데이터 + 정답
     ↓
   학습
     ↓
모델(학습된 규칙)
     ↓
새로운 데이터의 결과 예측
```

예를 들어 고양이와 강아지를 구별하는 프로그램을 사람이 `if`문만으로 만든다고 생각하면 매우 어렵다.

```text
귀가 뾰족하면 고양이?
털이 길면 고양이?
코가 크면 강아지?
```

실제 사진은 각도, 조명, 품종, 크기가 모두 다르기 때문에 사람이 모든 조건을 직접 적기 어렵다.

머신러닝은 여러 고양이와 강아지 사진을 이용해 **구별에 필요한 특징을 데이터로부터 학습**하도록 만든다.

# 4. 머신러닝과 딥러닝의 관계

처음에는 머신러닝과 딥러닝이 서로 완전히 다른 기술처럼 느껴졌지만 관계를 계층으로 보면 이해하기 쉽다.

```text
인공지능(AI)
└── 머신러닝(Machine Learning)
    └── 딥러닝(Deep Learning)
```

- **AI**: 인간의 지능적인 행동을 컴퓨터로 구현하려는 큰 분야
- **머신러닝**: 데이터를 이용해 패턴이나 규칙을 학습하는 AI 방법
- **딥러닝**: 여러 층의 인공신경망을 사용하는 머신러닝 방법

따라서 모든 AI가 딥러닝인 것은 아니고, 모든 머신러닝이 딥러닝인 것도 아니다.

# 5. Software 1.0과 Software 2.0

오늘 가장 흥미로웠던 개념 중 하나가 **Software 2.0**이었다.

## Software 1.0

기존 프로그램은 사람이 직접 규칙을 코드로 작성한다.

```python
if temperature >= 30:
    result = "더움"
elif temperature >= 20:
    result = "적당함"
else:
    result = "추움"
```

즉 프로그램의 행동 방식이 사람이 작성한 코드에 들어 있다.

```text
사람이 규칙 작성
→ 코드
→ 실행 결과
```

## Software 2.0

머신러닝에서는 사람이 모든 판단 규칙을 하나하나 작성하지 않는다.

대신 다음 요소를 준비한다.

- 데이터
- 원하는 목표
- 학습 방법
- 평가 기준

그리고 학습을 통해 모델의 가중치가 결정된다.

```text
데이터
  +
정답 또는 목표
  ↓
학습
  ↓
모델의 가중치
  ↓
예측 결과
```

Software 1.0에서 프로그램의 핵심이 사람이 작성한 코드라면, Software 2.0에서는 **학습된 모델 자체가 판단 규칙의 역할을 한다**고 볼 수 있다.

물론 실제 AI 서비스는 Software 1.0과 2.0 중 하나만 사용하는 것이 아니라 보통 함께 사용한다.

```text
일반 프로그램 코드
+ 데이터 처리 코드
+ 학습된 AI 모델
+ 데이터베이스/API/UI
= 실제 AI 서비스
```

# 6. AI 프로젝트는 모델보다 문제 정의가 먼저다

프로젝트를 생각할 때 처음에는 어떤 AI 모델을 쓸지를 먼저 떠올리기 쉽다.

하지만 오늘 정리하면서 다음 순서가 더 중요하다고 느꼈다.

```text
1. 누가 사용할 것인가?
2. 어떤 불편이나 문제를 해결할 것인가?
3. 어떤 데이터를 사용할 수 있는가?
4. AI가 정확히 어떤 판단 또는 생성을 해야 하는가?
5. 결과가 좋은지 무엇으로 평가할 것인가?
6. 실제 서비스에서는 결과를 어떻게 보여 줄 것인가?
```

예를 들어 단순히

> AI로 학습 서비스를 만든다.

라고 하면 범위가 너무 넓다.

조금 더 구체화하면 다음과 같이 생각할 수 있다.

```text
사용자: 프로그래밍 초보 학습자
문제: 배운 내용을 반복해서 연습하기 어렵다.
입력: 사용자의 문제 풀이 기록
AI 역할: 취약한 부분 분석 및 다음 문제 추천
출력: 개인별 연습 문제와 피드백
평가: 정답률 향상, 반복 오답 감소
```

이렇게 정리하면 어떤 데이터와 기능이 필요한지 훨씬 명확해진다.

# 7. 프로젝트용 AI 도우미를 사용할 때 배운 점

프로젝트 전용 AI 도우미를 사용할 때도 단순히 "이 프로젝트 도와줘"라고 하는 것보다 역할을 명확히 주는 것이 좋다.

예를 들어 다음 정보를 먼저 정리해 둘 수 있다.

```text
프로젝트 목적
사용자
현재 기술 스택
내 담당 역할
프로젝트 규칙
답변 형식
하지 말아야 할 것
```

이렇게 컨텍스트를 고정해 두면 매번 처음부터 프로젝트를 설명하는 시간을 줄일 수 있고, 여러 번 질문해도 비슷한 기준으로 답을 받을 수 있다.

AI를 잘 쓰는 것도 결국 **좋은 질문 한 번을 만드는 것보다 필요한 배경과 제약 조건을 정확히 전달하는 것**이 중요하다는 점을 느꼈다.

# 오늘 헷갈렸던 부분 정리

## AI = ChatGPT가 아니다

ChatGPT는 AI 기술을 활용한 서비스 중 하나다.

```text
AI
├─ 규칙 기반 AI
├─ 머신러닝
│  └─ 딥러닝
│     └─ LLM
└─ 다양한 AI 응용 서비스
```

## 튜링 테스트 통과 = 완벽한 지능이 아니다

튜링 테스트는 대화에서 인간처럼 보이는지를 판단하는 방식이지, 모든 지능을 검증하는 절대적인 시험은 아니다.

## 머신러닝 = 사람이 아무것도 안 하는 것이 아니다

모델이 규칙을 학습하더라도 사람은 여전히 다음 일을 해야 한다.

- 문제 정의
- 데이터 수집 및 정리
- 모델 선택
- 학습 방법 설정
- 결과 평가
- 잘못된 결과 수정

## Software 2.0 = 기존 코딩이 사라진다는 뜻이 아니다

AI 서비스를 만들려면 여전히 Python, 서버, 데이터베이스, API, UI 같은 일반 프로그램 코드가 필요하다.
