## 2. Chapter 01 — 첫 GET API

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def read_root():
    return {"message": "라면먹고갈래"}
```

구현한 API:

| Method | Path | 응답 |
| --- | --- | --- |
| GET | `/` | 200, JSON 메시지 |
| GET | `/members` | 200, 회원 2명 |
| GET | `/courses` | 200, 강좌 3명분의 데이터 |

강좌는 과제 조건에 맞춰 3개로 구성했다. 데이터베이스 대신 Python 리스트를 사용했다.

## 3. Chapter 02 — Path Parameter와 Query Parameter

Path Parameter는 특정 자원을 식별한다.

```text
GET /members/1
GET /courses/2
```

Query Parameter는 목록 검색과 필터에 사용한다.

```text
GET /members?name=kim
GET /members/filter/?min_age=20
GET /courses/filter/?title=front
GET /courses/filter/?level=2
```

회원 이름, 최소 나이, 강좌 제목과 레벨 조건을 구현했다. 검색은 대소문자를 무시하고, 여러 조건을 동시에 적용할 수 있다.

**HTTP 상태 코드의 차이**

- 200: 정상 조회. 조건에 맞는 값이 없으면 빈 배열일 수도 있다.
- 404: 형식은 올바르지만 해당 회원·강좌가 존재하지 않는다.
- 422: 정수여야 할 경로에 문자 등을 넣어 입력 검증에 실패한다.

특히 `/members/search/` 같은 고정 경로가 `/members/{member_id}`보다 먼저 등록돼야 한다는 점을 확인했다.

## 4. Chapter 03 — Request Body와 Pydantic

POST Request Body의 구조와 필수 타입을 Pydantic 모델로 선언했다.

```python
from pydantic import BaseModel

class MemberCreate(BaseModel):
    name: str
    email: str
    age: int

class CourseCreate(BaseModel):
    title: str
    instructor: str
    capacity: int
```

구현한 API:

- `POST /members`: 유효한 회원 Body를 받으면 **201 Created**
- `POST /courses`: 유효한 강좌 Body를 받으면 **201 Created**
- 필수 필드 누락·변환 불가능한 타입은 **422 Validation Error**

오류 응답의 `loc` 값으로 문제가 된 필드를 확인했다. 앞선 GET API 동작을 유지하는 회귀 테스트도 포함했다.

**중요한 구분:** 현재 POST 성공 시 반환하는 `id: 4`는 학습용 고정 임시값이다. DB가 없으므로 실제 데이터 저장, 새 ID 발급, 중복 방지는 구현되지 않았다.

Chapter 03 TestClient 검증 **23개 통과**. 실제 Chrome에서 POST Body를 입력하고 Swagger Execute로 확인하는 작업은 별도로 남아 있다.

## 7. WTI 선물 데이터와 롤오버

WTI는 개별 선물 계약과 여러 계약을 이어 붙인 연속 가격을 구별해야 한다. 계약 전환으로 생긴 가격 차이를 시장의 실제 하루 변동률이라고 해석하면 잘못된 결론을 얻을 수 있다.

오늘 연구용 무료 API 확인 기록:

```text
WTI 연속 가격: 22건
개별 계약 가격: 831건
대조: 연속 가격 22건과 해당 계약 가격 일치
관찰된 전환: 2026-10-13, CLX26 → CLZ26
```

이 결과는 해당 공급자의 응답을 확인한 것이지 공식 롤 규칙 전체를 입증한 것은 아니다. 잠정치(preliminary)나 정확한 공개 시각이 불명확한 데이터는 예측에 사용하지 않도록 보수적으로 처리했다.

## 9. 오늘의 핵심 정리

```text
Path Parameter = 특정 자원 식별
Query Parameter = 검색·필터
Request Body = JSON 등의 입력 데이터

200 = 정상 처리
201 = 생성 요청 처리
404 = 자원 없음
422 = 입력 검증 실패

201 Created ≠ 실제 DB 영구 저장
자동 TestClient 통과 ≠ Chrome 수동 검증 완료

데이터 수집 성공 ≠ 과거 시점에 실제로 알 수 있었던 정보
모델을 실행함 ≠ 예측력이 검증됨
연구 PR 작성 ≠ main 병합
```
