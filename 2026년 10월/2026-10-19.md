# 2. Raw 우선 저장 구조

Make에서 API 응답을 바로 행 단위로 쪼개 저장하지 않고 원본 배치를 raw_api_data 테이블에 먼저 저장하는 구조를 사용했다.

```text
Make
→ API 원문 4개를 Raw 한 건으로 저장
→ AFTER INSERT Trigger
→ DB 함수가 각각 정제
```

이 방식의 장점:

- 원본 응답 보존
- Make 시나리오 단순화
- 재처리 가능
- 오류가 나도 Raw에서 다시 확인 가능
- 수집과 정제 책임 분리

Raw 테이블은 공개 조회 권한을 주지 않고 관리용 데이터로 유지했다.

# 3. 관광 소비 지표 오류 발견

오늘 가장 중요한 수정 중 하나는 관광 소비 지표의 의미를 다시 확인한 것이다.

기존에는 코드 2201의 값을 관광소비강도로 사용하고 있었다.

하지만 실제 응답을 비교해 보니:

```text
2201 = 외지인 소비액
서울 2025-09 값 = 119.08

22 = 관광소비강도
서울 2025-09 값 = 97.07
```

둘 다 API 응답은 HTTP 200 / resultCode 0000이기 때문에 단순 성공 코드만 확인해서는 이 오류를 찾을 수 없었다.

API를 사용할 때는 성공 여부뿐 아니라 지표 코드, 지표명, 값의 의미까지 확인해야 한다.

# 4. 기존 잘못된 값은 삭제하지 않고 보존

기존 2201 / 119.08 값을 그냥 덮어쓰거나 삭제하지 않았다.

대신 다음 방식으로 수정했다.

- 기존 26행에 consumption_metric_code 추가
- 기존 값은 비공개 archive 테이블에 보존
- 새 처리 함수는 코드 22만 관광소비강도로 인정
- 기존 Raw 원문은 그대로 유지

즉 데이터 오류를 수정하면서도 과거에 어떤 값이 왜 사용됐는지 추적할 수 있게 했다.

데이터 수정에서는 최신 값만 맞추는 것보다 변경 이력을 보존하는 것도 중요하다.

# 16. 데이터 모델링 핵심 복습

SQLD 노트를 만들면서 데이터 모델링의 기본 개념도 다시 정리했다.

핵심:

```text
엔터티 ↔ 테이블
인스턴스 ↔ 행
속성 ↔ 컬럼
식별자 ↔ Key
```

모델링 단계:

```text
개념적
→ 논리적
→ 물리적
```

주식별자의 조건은 유일성·최소성·불변성·존재성으로 정리했다.

# 17. SQL 기초 분류

SQL 명령도 시험 기준으로 다시 분류했다.

```text
DML = SELECT / INSERT / UPDATE / DELETE
DDL = CREATE / ALTER / DROP / RENAME / TRUNCATE
DCL = GRANT / REVOKE
TCL = COMMIT / ROLLBACK / SAVEPOINT
```

특히 시험에서 자주 헷갈리는 SELECT는 DML, TRUNCATE는 DDL이라는 점을 강조했다.
