# 1. Chapter 15 — Book Explorer 통합 실습

오늘 Frontend Basic Chapter 15에서는 지금까지 따로 배운 HTML, CSS, JavaScript, Event, Form, HTTP, JSON, fetch(), DOM을 하나의 작은 프로젝트로 연결했다.

Book Explorer의 전체 구조:

```text
검색어 입력
→ submit Event
→ GET 요청
→ JSON 응답
→ 배열 저장
→ 목록 DOM 렌더링
→ 도서 클릭
→ 상세 DOM 렌더링

등록 Form 입력
→ submit Event
→ FormData
→ JavaScript Object
→ JSON.stringify()
→ POST 요청
→ Response
→ 성공/실패 메시지
```

# 2. GET 도서 검색

Open Library Search API를 사용해 검색 기능을 만들었다.

핵심 코드 흐름:

```javascript
submit
→ preventDefault()
→ keyword.trim()
→ searchBooks(keyword)
→ fetch(GET)
→ response.json()
→ data.docs
```

검색어는 encodeURIComponent로 URL에 안전하게 넣고 최대 10권을 조회하도록 구성했다.

응답 데이터가 예상한 docs 배열인지도 Array.isArray()로 검사했다.

# 3. 검색 결과와 상세 화면

검색 결과는 books 배열에 저장하고 각 항목을 button으로 렌더링했다.

표시 정보:

- 제목
- 저자
- 최초 출판연도

책을 클릭하면 다음 상세 정보를 표시한다.

- 제목
- 저자
- 최초 출판연도
- Open Library key

외부 API의 문자열을 innerHTML로 직접 넣지 않고 createElement()와 textContent를 사용했다.

# 4. POST 등록 요청

도서 제목과 저자를 입력해 JSONPlaceholder 테스트 API로 POST 요청을 보내는 기능도 구현했다.

```text
Form
→ FormData
→ { title, author }
→ JSON.stringify()
→ POST
```

중요한 점:

```text
HTTP POST 성공
≠ 실제 DB 영구 저장
```

JSONPlaceholder는 학습용 API이기 때문에 성공 응답이 왔다고 검색 결과 배열에 새 책을 임의로 추가하지 않았다.

# 6. Empty와 Error의 차이

이번 실습에서 다시 구분한 개념:

```text
Empty
= 요청 성공 + 결과 0건

Error
= HTTP 요청 또는 데이터 처리 실패
```

둘은 사용자에게 보여주는 의미가 다르기 때문에 같은 상태로 처리하면 안 된다.

# 13. Upstage Solar RAG 특강 준비

오늘 별도로 Upstage Solar를 이용한 RAG 특강 환경도 준비했다.

특강의 전체 구조:

```text
서울시 조례 수집
→ 문서 Parse
→ Chunk
→ Embedding + Keyword 검색
→ Solar 답변

```

RAG는 질문을 바로 LLM에게 보내는 것이 아니라 관련 문서를 먼저 검색한 뒤 그 근거를 같이 전달해 답하게 하는 방식이다.

# 14. RAG 핵심 개념

오늘 정리한 기본 용어:

```text
RAG
= 검색으로 근거를 찾고 LLM이 그 근거를 이용해 답변

Chunk
= 검색하기 좋게 문서를 작은 단위로 나눈 조각

Embedding
= 문장의 의미를 숫자 벡터로 표현
```

단순 LLM 질의보다 근거 문서를 같이 사용하는 것이 핵심이다.

# 17. PowerShell 5.1 인코딩 문제

처음 작성한 설치 스크립트에는 한국어 문자열이 포함되어 있었다.

Windows PowerShell 5.1은 UTF-8 BOM이 없는 파일을 레거시 코드페이지로 읽으면서 ParserError를 발생시켰다.

해결:

```text
설치 스크립트를 ASCII-only로 변경
```

즉 코드 자체의 PowerShell 문법이 틀린 것이 아니라 파일 인코딩과 실행 환경의 조합이 문제였다.

Windows 자동화에서는 PowerShell 버전과 파일 인코딩도 함께 고려해야 한다.

# 20. Gemini SDK 경고 수정

데이터분석 Chapter 14-1 코드에서는 Gemini SDK 실행 시 사용하지 않는 Automatic Function Calling 관련 경고가 발생할 수 있어 설정을 수정했다.

이번 과제에서는 함수 도구를 사용하지 않기 때문에 generate_content()에 AFC 비활성화 설정을 추가했다.

```text
automatic_function_calling.disable = true
```

기존 429 / 503 재시도 로직은 그대로 유지했다.

즉 실제로 사용하지 않는 기능은 명시적으로 꺼 불필요한 SDK 경고를 줄였다.
