# 1. HTML의 역할

HTML은 화면을 예쁘게 만드는 기술이 아니라 문서의 구조와 의미를 정의하는 언어다.

```text
HTML = 구조
CSS = 표현
JavaScript = 동작
```

현재 단계에서는 디자인보다 어떤 내용이 제목인지, 본문인지, 어떤 콘텐츠가 같은 영역에 속하는지를 정확하게 표현하는 것이 중요하다.

# 2. HTML 문서의 기본 구조

기본적인 HTML 문서는 다음 구조를 가진다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>문서 제목</title>
</head>
<body>
    <h1>화면에 보이는 제목</h1>
    <p>화면에 보이는 본문입니다.</p>
</body>
</html>
```

각 요소의 역할:

- `<!DOCTYPE html>`: HTML5 문서임을 브라우저에 알림
- `<html>`: HTML 문서 전체를 감싸는 최상위 요소
- `<head>`: 문자 인코딩, 문서 제목, CSS 연결, 메타데이터 등 문서 정보
- `<body>`: 실제 화면에 표시되는 콘텐츠

# 3. 태그, 요소, 속성

예:

```html
<p class="description">Frontend를 학습합니다.</p>
```

구분:

```text
<p>, </p>
= 태그(tag)

<p class="description">Frontend를 학습합니다.</p>
= 요소(element)

class="description"
= 속성(attribute)
```

속성은 요소에 추가 정보를 제공한다.

예를 들어 `<html lang="ko">`의 `lang="ko"`는 문서의 기본 언어가 한국어라는 의미다.

# 4. HTML은 트리 구조다

HTML 요소는 단순히 위에서 아래로 나열되는 것이 아니라 부모·자식 관계를 가진다.

예:

```html
<body>
    <main>
        <section>
            <h2>회원 소개</h2>
        </section>
    </main>
</body>
```

트리로 표현하면:

```text
body
└─ main
   └─ section
      └─ h2
```

- body는 main의 부모
- main은 body의 자식
- 같은 부모를 가진 요소는 형제

이 관계는 나중에 DOM을 다룰 때 그대로 연결된다.

# 5. 시멘틱 HTML

모든 영역을 `div`로 만들 수도 있지만 그러면 각 영역이 무엇을 의미하는지 코드만 보고 바로 알기 어렵다.

HTML5에서는 역할을 가진 시멘틱 태그를 사용할 수 있다.

| 태그 | 의미 |
| --- | --- |
| `header` | 문서 또는 영역의 머리말 |
| `nav` | 주요 탐색 링크 |
| `main` | 문서의 핵심 콘텐츠 |
| `section` | 주제별 콘텐츠 영역 |
| `article` | 독립적으로 의미 있는 콘텐츠 |
| `aside` | 부가 콘텐츠 |
| `footer` | 문서 또는 영역의 하단 정보 |

시멘틱 HTML을 사용하면 사람이 코드를 읽기 쉽고 문서 구조도 더 명확해진다.

# 7. 링크 — a 태그

링크는 다른 페이지나 위치로 이동할 때 사용한다.

```html
<a href="https://github.com/...">
    수업용 GitHub 열기
</a>
```

핵심은 다음과 같다.

```text
href
= 이동할 목적지

링크 텍스트
= 사용자가 실제로 클릭하는 글자
```

새 탭에서 열고 싶다면 `target="_blank"`를 사용할 수 있다.

# 8. 이미지 — img 태그

이미지는 `src`에 이미지 위치를 지정한다.

```html
<img src="profile.png" alt="회원 프로필 이미지">
```

핵심 속성:

```text
src
= 이미지 위치

alt
= 이미지를 대신 설명하는 대체 텍스트
```

`alt`는 이미지가 깨졌을 때뿐 아니라 보조 기술이 이미지의 의미를 전달할 때도 중요하다.

따라서 단순히 `alt="image"`라고 쓰기보다 이미지가 무엇을 의미하는지 설명하는 것이 좋다.

# 9. HTML Table

회원 목록처럼 행과 열로 반복되는 데이터는 `table`로 표현할 수 있다.

기본 구조:

```text
table
├─ thead
│  └─ tr
│     └─ th
└─ tbody
   └─ tr
      └─ td
```

역할:

- `table`: 표 전체
- `thead`: 컬럼 제목 영역
- `tbody`: 실제 데이터 영역
- `tr`: 한 행
- `th`: 제목 셀
- `td`: 데이터 셀

DB를 배운 경험과 연결하면 다음처럼 생각할 수 있다.

```text
Database Table
→ Rows / Columns
→ HTML Table
→ 사용자가 보는 목록
```

단, 둘은 역할이 다르다.

```text
Database Table
= 데이터 저장

HTML Table
= 데이터 화면 표시
```

# 10. Form

Form은 사용자가 입력하는 여러 값을 한 영역에 묶는 HTML 구조다.

예:

```html
<form>
    <label for="name">이름</label>
    <input id="name" name="name" type="text">

    <label for="email">이메일</label>
    <input id="email" name="email" type="email">

    <button type="submit">회원 등록</button>
</form>
```

현재 단계에서는 입력 화면 구조를 만드는 것이 목표다.

버튼을 눌렀다고 바로 Database에 저장되는 것은 아니다.

앞으로 다음처럼 연결된다.

```text
HTML Form
→ JavaScript
→ HTTP 요청
→ FastAPI
→ Database
```

# 11. label, id, name 차이

Form에서 가장 헷갈리기 쉬운 부분이다.

```html
<label for="email">이메일</label>
<input id="email" name="email" type="email">
```

정리:

```text
label
= 사용자에게 보여주는 입력 항목 이름

id
= HTML 문서 안에서 요소를 찾는 식별자

name
= 입력 데이터를 구분하는 이름
```

`label for`와 `input id`를 같은 값으로 연결하면 어떤 label이 어떤 입력칸을 설명하는지 명확해진다.

`name`은 이후 JavaScript, Form 데이터, API 전송 단계에서 중요해진다.
