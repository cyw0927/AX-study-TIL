# 1. GMIA 프로젝트 시작

오늘 새로 만든 프로젝트의 이름은:

```text
GMIA
Global Macro Intelligence Agent
```

목표는 단순히 주가를 맞히는 프로그램이 아니라 여러 종류의 정보를 같이 보고 금융시장의 움직임을 설명하는 개인용 분석 에이전트를 만드는 것이다.

분석 대상:

- 각국 경제상황
- 정책금리와 국채금리
- 주식시장
- 환율
- 금·원유 등 원자재
- Bitcoin 등 암호화폐
- 기업 실적과 가치평가
- 국제정세와 지정학
- 공급망·해운·제재

# 2. 보고서보다 예측 구조를 먼저 설계

오늘 프로젝트 방향은 단순히 매번 경제 보고서를 작성하는 데 두지 않았다.

장기적으로는 다음 흐름으로 발전시키는 것이 목표다.

```text
데이터 수집
→ 경제·시장 상태 판단
→ 변수 간 관계 분석
→ 시나리오 생성
→ 예측
→ 실제 결과와 비교
→ 모델 수정
```

현재 v0.1에서는 실제 예측모델 코딩보다 먼저 어떤 데이터와 판단 기준이 필요한지 정의하는 개념검증 단계로 시작했다.

# 3. 거시경제 분석 범위

국가별 경제를 단순 GDP 하나로 판단하지 않고 여러 지표를 함께 보도록 설계했다.

주요 지표:

- GDP 성장률
- CPI / 근원물가 / PPI
- 실업률과 고용
- 실질임금과 가처분소득
- 소비와 소매판매
- 산업생산
- 제조업·서비스업 PMI
- 무역수지와 경상수지
- 정책금리
- 국채금리와 장단기 금리차
- 정부·민간부채
- 환율과 외환보유액
- 부동산
- 원자재 가격

각 국가를 성장/물가 조합이나 금융위기·정책전환 같은 경기국면으로 분류하는 구조도 넣었다.

# 4. 금융시장 분석 범위

주식만 분석하지 않고 주요 자산을 같이 보도록 했다.

예:

```text
주식
S&P 500 / NASDAQ / KOSPI / Nikkei / 중국·유럽 지수

채권
미국·한국·일본·독일 국채

외환
USD/KRW / USD/JPY / EUR/USD / DXY

원자재
금 / 은 / WTI / Brent / 천연가스 / 구리

암호화폐
Bitcoin / Ethereum
```

1일, 1주, 1개월, 3개월, 6개월, 1년 등 기간별로 수익률과 변동성을 구분하는 원칙도 넣었다.

# 5. PER·PBR을 단독 판단 기준으로 사용하지 않기

기업 분석에서는 PER이나 PBR이 낮다는 이유만으로 저평가라고 결론내리지 않도록 규칙을 정했다.

함께 볼 항목:

- PER
- PBR
- ROE
- ROIC
- EPS 성장률
- 매출 성장률
- 영업이익률
- 현금흐름
- 부채
- 배당
- 자사주 매입·소각
- EV/EBITDA
- 시장 기대치

특히 금융업·제조업·성장주처럼 산업별로 평가 방식이 다르다는 점도 반영했다.

# 6. 국제정세 분석 원칙

국제정세는 뉴스 제목의 긍정/부정 감성으로 판단하지 않고 실제 경제적 파급경로를 보도록 설계했다.

예:

```text
해상운송로 긴장
→ 운임
→ 원유·원자재 비용
→ 물가
→ 기업 마진
→ 금리 기대
→ 주식·채권·환율
```

또 다음을 반드시 구분하도록 했다.

- 확인된 사실
- 당사국 주장
- 제3자 검증
- AI의 추론

같은 원출처를 반복 인용한 여러 기사를 독립적인 다중 검증으로 계산하지 않는 원칙도 넣었다.

# 8. SIMULATION MODE와 REAL DATA MODE 분리

오늘 설계에서 가장 중요하게 구분한 것은 가상 실험과 실제 데이터 분석이다.

```text
SIMULATION MODE
= 가상 수치와 가상 사건으로 분석 구조 실험

REAL DATA MODE
= 실제 확인 가능한 데이터만 사용
```

가상 실험에서 나온 수치나 확률을 실제 백테스트 결과처럼 표현하지 않도록 명시했다.

실제 모드에서는 데이터 기준일과 발표일을 구분하고 과거 시점 분석에 미래 정보를 사용하지 않는 규칙을 넣었다.

- 추가로 필요한 데이터

# 19. 오늘의 회고

오늘은 경제·금융 데이터를 단순히 한 번 분석해 주는 보고서를 만드는 것보다, 반복적으로 데이터를 받고 판단을 수정할 수 있는 분석 시스템의 틀을 만드는 데 집중했다.

특히 국제정세와 금융시장을 함께 다룰 때 한 사건을 바로 상승·하락으로 연결하면 지나치게 단순해질 수 있기 때문에, 실제 파급경로와 반대 시나리오를 반드시 보도록 규칙을 넣었다.

또 ChatGPT와 Claude가 서로 결과를 검증하게 설계하면서 AI 두 개의 합의 자체를 정답으로 취급하지 않고, 근거와 데이터가 무엇인지 다시 확인하는 구조를 만들었다.

다음 단계에서는 이 프롬프트 기반 실험을 넘어 실제 데이터 수집과 정량 예측모델을 어떤 방식으로 구현할지 구체화해야 한다.
