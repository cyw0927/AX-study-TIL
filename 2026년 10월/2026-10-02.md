# 1. 전체 과정 구조

이번 과정은 Frontend만 따로 배우는 수업이 아니라 다음 단계로 이어진다.

```text

    ↓

    ↓
```

```text

Backend API
  ↓

```

# 2. Browser / Web Server / API Server

오늘 가장 먼저 구분한 개념이다.

## Browser

사용자가 실제 화면을 보는 프로그램이다. HTML, CSS, JavaScript를 받아 해석하고 화면에 표시한다.

## Web Server

HTML, CSS, JavaScript, 이미지 같은 파일을 브라우저에 제공한다.

이번 실습에서는 VS Code Live Server가 이 역할을 한다.

## API Server

화면 파일이 아니라 데이터와 기능을 제공한다.

```text
Browser JavaScript
  ↓ fetch()
API Server
  ↓
JSON Response
```

Frontend가 Database에 직접 접근하는 것이 아니라 보통 Backend/API Server를 통해 연결된다.

# 3. localhost와 포트

localhost는 현재 사용 중인 내 컴퓨터를 의미한다.

예:

```text
http://localhost:5500/
```

```text
http       = 통신 방식
localhost  = 내 컴퓨터
5500       = 서버 프로그램을 구분하는 포트
```

한 컴퓨터에서 여러 서버 프로그램을 실행할 수 있기 때문에 포트 번호로 각각 구분한다.

# 4. HTML / CSS / JavaScript 역할

| 기술 | 역할 | 쉽게 생각하면 |
| --- | --- | --- |
| HTML | 정보 구조 | 골격 |
| CSS | 표현과 배치 | 디자인 |
| JavaScript | 데이터와 동작 | 행동 |

앞으로 이 세 가지가 DOM, Event, Form, HTTP, fetch와 연결된다.

# 5. DevTools

브라우저 개발자 도구는 실행 결과를 검증하는 Evidence 역할을 한다.

- Elements: HTML/DOM 구조와 CSS 확인
- Console: JavaScript 실행 결과와 오류 확인
- Network: HTTP Request/Response 확인

화면이 보인다는 이유만으로 완료라고 판단하지 않고 Elements, Console, Network까지 확인하는 습관이 중요하다.

# 6. AI를 사용하는 개발 방식

이번 과정에서는 AI가 코드를 대신 작성하는 것보다 사람이 개발 흐름을 설명하고 검증할 수 있어야 한다.

AI가 만든 코드라도 다음 질문에 답할 수 있어야 한다.

- 무엇을 만들고 있는가?
- 입력 데이터는 어디서 오는가?
- 어떤 서버로 요청하는가?
- 정상 결과는 무엇인가?
- 오류가 나면 어디부터 확인해야 하는가?

공통 개발 루프:

```text
요구사항
→ 구조 / 데이터 흐름 이해
→ 완료 조건 정의
→ AI 구현 계획
→ 작은 단위 구현
→ Browser 실행
→ DevTools 확인
→ 오류 분석
→ 수정
→ 재검증
→ Git Commit / Push
```

# 11. 아직 확인하지 않은 것

파일 작성과 GitHub 반영은 완료했지만 실제 브라우저 실행 Evidence는 아직 확인하지 않았다.

- [ ] Live Server 실행 확인
- [ ] localhost 또는 127.0.0.1 접속 확인
- [ ] DevTools Network에서 HTML GET 요청 확인

실제로 확인하지 않은 항목은 완료했다고 적지 않는 것이 중요하다.
